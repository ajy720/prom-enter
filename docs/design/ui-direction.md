# 화면 방향과 디자인 토큰

확정일: 2026-11-02. 사용자가 제공한 레퍼런스와 배치 요청 기준.

## 확정한 방향

- [대화 화면 참고](reference-dialogue.jpg): 배경과 캐릭터가 중심인 비주얼 노벨 구성. 화면 하단에 발화자와 대사를 표시하고, 그 바로 아래에 채팅 입력창을 둔다.
- 스탯은 데스크톱 화면의 왼쪽 상단~중간에 세로 패널로 표시한다.
- [선택 화면 참고](reference-choices.jpg): 선택 상황에는 배경 위 중앙에 넓은 선택지 버튼을 세로로 배치한다. 선택 메뉴가 열려 있는 동안 뒤쪽 대화 입력은 비활성화한다.
- **현재 색상 방향은 화이트 베이스 + 연핑크 포인트다.** [사용자 지정 팔레트](https://coolors.co/palette/d8e2dc-ffe5d9-ffcad4-f4acb7-9d8189): `#D8E2DC`, `#FFE5D9`, `#FFCAD4`, `#F4ACB7`, `#9D8189`. 이전 팔레트는 더 이상 적용 기준으로 사용하지 않는다. 현재 색상 미리보기: [시작](preview-white-pink-title.jpg), [대사창](preview-white-pink-dialogue.jpg).
- 참고 이미지는 배치·분위기 연구용이다. 이미지 속 캐릭터·배경·문구는 게임 자산으로 사용하지 않는다.
- **캐릭터 표현은 실사 사진 기준이다.** 현재 일러스트는 위치 확인을 위한 임시 자산이며 최종 미술 방향이 아니다.

## 실사 이미지 적용 기준

- 사진을 받기 전에도 화면·입력·선택 기능을 개발한다. 받은 뒤 인물 크기·위치·여백과 패널 투명도를 실제 사진에 맞춰 조정한다.
- 흰색을 화면과 패널의 기본색으로 사용하고 연핑크는 이름표·선택 표시·주요 버튼에 사용한다. 세이지와 피치는 보조 배경에 소량 사용한다. 실사 사진의 피부와 의상에 색상 필터를 씌우지 않는다.
- 장식과 광택은 절제하고 부드러운 테두리·그림자를 사용한다. 캐릭터 뒤의 임시 빛 효과는 실제 사진 적용 시 필요성을 재검토한다.
- 투명 배경의 인물 PNG/WebP라면 장면 배경과 분리해서 배치한다. 배경이 포함된 사진은 자동으로 누끼 이미지처럼 다루지 않고 프레이밍을 따로 조정한다.
- 이미지를 늘려 왜곡하지 않고 원본 비율을 유지한다. 얼굴·머리 위쪽은 UI에 가리지 않도록 하고, 대사창은 가능한 한 몸통 아래쪽에 겹치게 한다.
- 사진마다 구도와 인물 위치가 다르면 크기·기준 위치를 개별 조정한다. 모든 사진에 같은 자르기 설정을 강제하지 않는다.
- 표정 사진이 여러 장이면 사진마다 크기와 인물 위치를 맞춰 대화 중 교체할 때 인물이 튀지 않게 한다. 없는 표정을 임의로 생성하지 않는다.
- 사진 수령 시 인물/배경 분리 여부, 전신/상반신 구도, 해상도, 표정별 파일을 확인한다. 이는 지금 개발을 시작하기 위한 필수 준비물이 아니다.

## 적용한 기준

기준값은 `frontend/src/tokens.css`에 모았다. 어두운 글자색과 흰색은 파스텔 위에서 읽을 수 있도록 추가한 보조색이다.

| 토큰 | 역할 |
|---|---|
| `--white`, `--surface` | 흰색 기본 배경과 패널 |
| `--pink`, `--pink-soft`, `--rose` | 주요 버튼·이름표·호버 강조 |
| `--sage`, `--peach`, `--mauve` | 보조 배경·중성 테두리 |
| `--surface-tint` | 흰색에 연핑크를 소량 혼합한 배경 |
| `--ink`, `--ink-muted`, `--accent` | 본문, 보조 설명, 강조 |
| `--glass`, `--dialogue-surface`, `--choice-surface` | 배경 위 패널과 대사·선택 영역 |
| `--space-1` ~ `--space-7` | 4·8·12·16·24·32·48px 간격 |
| `--radius-small`, `--radius-panel`, `--radius-dialogue` | 10·18·24px 모서리 |
| `--font-body`, `--text-dialogue` | 한국어 글꼴과 대사 크기 |

- 데스크톱: 왼쪽 스탯, 가운데 캐릭터, 오른쪽 사건 안내, 하단 대사와 입력.
- 좁은 화면: 사건 안내 → 압축한 스탯 → 캐릭터 → 대사 → 입력 순서로 재배치한다.
- 대사는 기본 16~19px, 읽기 편한 줄 간격을 적용한다. 긴 대사는 대사 영역 안에서 스크롤한다.
- 한 턴에 여러 발화가 있으면 이전·다음 대사로 읽는다. 전체 대화·기억·증거·처리 내역은 기록 창에서 확인한다.
- 로딩·빈 기록·실패·재시도·사용한 선택·키보드 포커스를 포함한다. 움직임 최소화 설정을 따른다.

## 이번 구현의 범위와 후속 작업

### 시작·소개 화면 추가 (2026-11-02)

- [시작 화면 참고](reference-title.png): 데스크톱에서 왼쪽 사진, 오른쪽 제목·게임 시작 버튼. 모바일에서는 사진 위·제목 아래로 배치한다.
- 게임 시작 후 대표실 도입 → 비서 환영 → 호칭 입력 → 회사 상황 안내 → 기존 데뷔조 프로필 제공 → 연습실 이동 → 서연·혜린·지우 개별 소개 → 면담 안내·상대 선택으로 연결한다.
- [프로필·선택 참고](reference-profiles.png): 기존 멤버는 '데뷔조 프로필 보기' 버튼으로 열리는 카드 목록·상세 패널에 표시한다. 면담 상대 선택도 같은 카드 구조를 사용한다.
- [신입 소개 참고](reference-introduction.png): 왼쪽 반신 사진, 오른쪽 첫 인사·활동명·나이·포지션·짧은 소개를 표시한다.
- 노션의 도입을 화면용으로 축약·각색했다. 계약·데뷔 기간 충돌은 확정하지 않았다.
- 신입 후보는 서연·혜린·지우의 공개 소개를 사용한다. 면담 상대 선택 이후 데모 면담과 별도 영입 확인을 연결했다. 실제 AI와 월별 게임 연결은 후속 작업이다. [면담 동작과 검증](../interview-demo.md)을 참고한다.
- 도입 단계·호칭·면담 상대는 이 브라우저에 별도로 저장한다. 기존 서버 저장은 덮어쓰지 않고 시작 화면의 '이전 축약 데모 이어하기'로 열 수 있다.
- API와 AI 호출 계약은 이번 추가에서 변경하지 않았다.
- 사진은 아직 없어 중성적인 자리 표시를 사용한다. [프로듀서 사진 요청 목록](photo-request.md)에 수량·구도·파일명·연결 위치를 정리했다.
- 데스크톱 1440px·모바일 390px에서 시작·소개·선택 화면을 확인했다. 호칭 공백 시 진행 방지, 호칭 반영, 기존 멤버 프로필 전환·닫기, 세 후보 소개 순서, 면담 상대 선택·새로고침 후 이어하기를 확인했다.
- 시작·도입에서 새 AI 요청이나 게임 생성 요청은 발생하지 않는다. 이번 범위의 브라우저 저장과 기존 서버 플레이 저장은 별개다.

### 기존 축약 데모 화면

- 기존 축약 데모 API와 게임 규칙에 새 UI를 적용했다. Part 1~2 새 스토리나 실제 AI 계약은 이번 변경에 포함하지 않았다.
- 기존 캐릭터 A/B/C와 SVG는 임시 자산이다. 서연·혜린·지우 설정과 실제 이미지 연결은 후속 작업이다.
- 배경은 CSS로 만든 연습실 시안이다. 실제 배경 이미지로 교체할 수 있다.
- 선택지는 '활동 선택'에서 열 수 있다. 현재 예능 제안과 계약 결정 장면에서는 자동으로 연다. 이는 기존 이벤트 ID에 연결한 임시 UI 규칙이다.
- 이후 새 스토리 연결 시 대화/선택 모드를 콘텐츠 또는 API의 명시적 필드로 정의하고, 선택 필수 여부와 취소 가능 여부도 함께 정한다.

## 확인 기록

- 프론트 프로덕션 빌드 통과.
- 브라우저에서 한글 대화 전송, 응답 표시, 스탯 변경, 대화 기록, 선택 실행·사용한 선택 비활성화 확인.
- 데스크톱 1440px, 모바일 390px에서 배치 확인. 모바일 가로 넘침 없음.
- 새로고침 후 저장 복원, 1→6개월차 전환 시 선택지 자동 표시, 훈련 없이 활동 확정 시 서버 오류 표시와 이후 정상 진행 확인.
- 실제 IME 조합 입력과 네트워크 실패 재시도는 자동 UI 검증에서 재현하지 않았다. 기존 오류 처리와 조합 입력 방지 코드는 유지한다.
