# 테스트와 AI 평가

[문서 안내](../README.md) · [설치 및 실행](setup.md)

아래 명령은 로컬 의존성을 설치한 뒤 프로젝트 루트에서 실행합니다. Windows에서는 가상환경 Python을 `backend/.venv/Scripts/python.exe`로 바꿉니다.

## 변경별 확인 방법

| 변경 | 확인할 것 |
|---|---|
| 백엔드·AI 코드 | 관련 pytest와 영향을 받는 게임 경로 |
| 프런트 코드 | 프로덕션 빌드와 바뀐 화면의 실제 동작 |
| AI·웹 연결 계약 | 양쪽 검증, 데모 입력 → 응답 → 상태 반영, 저장·복원 |
| 기획·캐릭터·콘텐츠 | 컴파일 결과·원문 동기화, 사건 판정·공개 조건 |
| 문서 | 링크·앵커·경로·명령·현재 코드와의 일치 |

## 자동 테스트와 빌드

```sh
backend/.venv/bin/python -m pytest -q backend/tests
npm --prefix frontend run build
```

자동 테스트는 성공/부분 성공/실패, 중복 요청·경합, 소유자 분리, 모델 실패 시 저장 방지, 허구의 행동·발화 근거 거부, 단서 비공개, 약속과 실행 구분, 반복 보상 제한, 순수 상태 계산을 확인합니다. pytest에서 실제 OpenAI 요청은 발생하지 않습니다.

## 오프라인 AI 평가

```sh
backend/.venv/bin/python scripts/evaluate_ai.py
backend/.venv/bin/python scripts/evaluate_ai.py --output backend/data/evals/latest.json
```

기본 실행은 환경 변수의 provider 설정과 무관하게 `demo`입니다. 분석 28개와 대사 5개를 실행합니다. 대사는 형식·권한 검사 후 사람 검토용 결과와 평가 기준을 남깁니다. 자동 통과 수를 대사 품질 점수로 해석하면 안 됩니다.

## 실제 모델 평가

```sh
backend/.venv/bin/python scripts/evaluate_ai.py --provider openai --allow-paid --output backend/data/evals/openai.json
```

실제 호출은 두 플래그와 서버 환경 변수의 키·모델이 있어야 합니다. 평가 사례의 단어를 외워 통과하는지 외에도 낯선 표현, 부정·가정·회상, 장기간 기억, 캐릭터별 말투, 단서 유출, 지연·사용량을 추가 검토하세요.

실제 모델 평가는 [설정](setup.md#환경-변수와-실제-ai-연결)을 마친 뒤 과금 범위를 확인하고 실행합니다. 최신 7명 페르소나·장기 기억·청중 전환·전체 분기 판단은 짧은 표본과 구분해 평가해야 합니다. 남은 평가 작업은 [개발 계획](../planning/roadmap.md)에 있습니다.

## 서버 프로토타입 점검

시작 화면에서 ‘후보 면담 시작’으로 이도 → 여울 → 사야 면담을 마무리하고 한 명을 선발합니다. 1~6개월차를 진행한 뒤 결과를 확인합니다. 선택 신입별 경로·성공/실패·자금 부족·중복 효과·후보별 대화 분리·저장/복원을 점검합니다. 판정표는 [Part 1–2 프로토타입](../development/part2-prototype.md)을 따릅니다.

브라우저 전용 도입·면담·첫 달 계획은 서버 플레이와 별도 저장됩니다. [면담](../development/interview-demo.md)과 [첫 달](../development/month-one-demo.md)의 구현 범위에 따라 확인합니다.

프런트 상태 테스트는 프로젝트 루트에서 실행합니다.

```sh
node --test frontend/tests/*.test.mjs
```

## 축약 플레이 수동 점검

캐릭터 선택 직후와 사건이 바뀔 때 대화창에 **시간·장소·상황·백하연의 설명·이번 선택지**가 표시됩니다. 도입 자체는 모델을 호출하지 않으며, 이전 플레이도 현재 사건의 안내를 복원합니다. 상세 계약은 [프런트엔드 연결 명세](../development/frontend-integration.md#첫-시작사건-전환)에 있습니다.

1. 연습생 선택 후 **예능 훈련 → 활동 확정 → 신입 출연**을 선택하면 훈련 이력에 따라 성공합니다. 휴식만 하고 신입을 출연시키면 실패합니다.
2. 조사 장면에서 **SNS 기록·친구 하나·상담 기록**을 확인합니다. 증거 3개를 모아도 사용자가 최종 대응을 고를 때까지 조사가 계속됩니다.
3. **조사 결과로 신입 보호**를 선택하면 증거 수에 따라 성공·부분 성공·실패가 나뉩니다. 책임 인정 선택은 실패 경로입니다.
4. 계약 장면에서 **결말 확인**을 누르면 결과·팀워크·신뢰에 따라 결말을 계산합니다. 최선의 결말에는 훈련 성공, 조사 성공, 장면별 격려가 도움이 됩니다.
5. 새로고침 후 복원, 이미 실행한 선택의 중복 방지, 기억·증거·처리 내역 탭을 확인합니다.

데모의 자유 입력은 **보수적인 규칙 기반 입력기**입니다. 명시적으로 작성한 한국어 명령 패턴과 제한된 대명사 참조를 처리하며, 일반적인 한국어 의미 이해를 구현했다고 간주하면 안 됩니다. 버튼 이름 또는 지원 명령으로 활동할 수 있고, `네 잘못이 아니야`, `괜찮아, 같이 해결하자`는 격려 예시, `내가 기록을 확인해줄게`는 약속 예시입니다. 미지원 문장은 대화로 처리하거나 되묻습니다. 부정·회상·가정 등의 제한된 오프라인 사례를 검증했고, 일반적인 의미 해석은 실제 모델 및 추가 평가로 검증해야 합니다.
