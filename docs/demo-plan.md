## 현재 구현된 도입 UI (2026-11-02)

2026-11-03: 영입 뒤 프로뮤 결성과 1개월차 첫 합숙의 과제·대화·계획 확정 프론트를 연결했다. [첫 달 데모](month-one-demo.md)를 참고한다. 실제 월별 판정·수치·서버 저장은 여전히 후속 작업이다.

- 아래의 Part 1~2 전체 완료 기준은 여전히 개발 계획이다. 도입 UI 완성을 전체 시나리오 완성으로 간주하지 않는다.

- **구현 제안:** 화면 구분, 버튼 이름, 면담 종료 방식, 단계별 개발 순서와 완료 기준. 팀 확정 사양으로 간주하지 않는다.

## 2. 플레이 흐름

```text
시작·배경 안내
  → 비서의 진행 설명
  → 연습생 1·2·3 면담
  → 신입 한 명 최종 선택
  → 팀과 목표 안내
  → 1개월차 합숙
  → 2개월차 포지션 갈등
  → 3개월차 리허설
  → 4개월차 쇼케이스
  → 5개월차 음원·음악방송 및 홍보
  → 6개월차 반기 결산·예능 출연 결정
  → 이번 데모 종료
```

원안의 배경은 기존 멤버 3명에 신입 1명을 합류시켜 팀을 운영하는 것이다. 면담 중 대화 상대를 바꾸는 행위와 최종 영입 확정은 별개다. 선택 이후 월별 결정과 결과가 다음 장면의 상태에 영향을 준다.

## 3. 화면 목록과 동작 — 구현 제안

여기서 화면은 사용자가 경험하는 단계를 뜻한다. 모두 별도 페이지로 만들 필요는 없고 공통 게임 화면에서 장면과 내용을 바꿔 재사용한다.

| 화면 | 표시할 정보 | 사용자 동작 | 다음 단계 |
|---|---|---|---|
| 시작·배경 | 회사 상황, 대표 역할, 게임 목표 | 시작하기 | 비서 안내 |
| 비서 안내 | 면담 방법, 신입 선발 안내 | 연습생 만나기 | 면담 |
| 연습생 면담 | 3명 목록, 현재 상대의 이름·소개·이미지, 해당 상대와의 대화, 면담 진행 상태 | 상대 선택, 질문 입력·전송, 면담 마무리 | 최종 선택 |
| 최종 선택 | 후보 3명과 소개, 현재 선택한 후보 | 후보 선택, 영입 확인, 면담으로 돌아가기 | 팀 안내 |
| 팀·목표 안내 | 기존 멤버 3명과 신입, 프로뮤(Promyou), 2년 계약과 월 단위 활동 설명 | 운영 시작 | 1개월차 |
| 월별 게임 | 현재 월·장소·사건·목표, 캐릭터, 대화, 상태 수치, 활동과 결정 | 대화·활동, 최종 결정 | 결과 표시 후 다음 월 |
| Part 2 마무리 | 6개월차까지의 결정·주요 상태·기록, 데모 완료 안내 | 기록 확인, 새 플레이 시작 | 종료 또는 새 플레이 |

### 공통 게임 화면에 필요한 요소

- 상단: 현재 단계 또는 월, 사건 제목, 저장·응답 대기 상태.
- 캐릭터 영역: 대화 상대와 이미지. 비서 발화는 연습생 발화와 이름으로 구분한다.
- 대화 영역: 사용자 입력과 응답, 긴 대화의 스크롤, 메시지 입력창과 전송 버튼.
- 진행 영역: 사건 설명, 이번 목표, 가능한 활동, 최종 결정 버튼.
- 상태 영역: 팀워크, 피로도, 신입 신뢰, 인지도, 팬 수, 자금. 신입 능력치는 원안에 필요하지만 현재 코드에는 없으므로 추가 항목을 협의한다.
- 결과 영역: 결정 결과, 상태 변화, 다음 단계 안내. 플레이어에게 비공개인 판정 조건은 노출하지 않는다.
- 빈 대화·응답 대기·전송 실패·재시도·플레이 복원 상태도 포함한다.

## 4. Part 2 월별 콘텐츠 — 원안에서 확인

표의 과제는 원안의 의미를 요약한 것이다. 실제 버튼과 데모 입력 문구는 아직 확정하지 않았다.

| 월 | 사건 | 플레이어 과제 | 화면에 필요한 변화 |
|---|---|---|---|
| 1 | 어색한 첫 합숙 | 신입 훈련 분야 지정, 기존 멤버 면담, 합숙 규칙 결정 | 훈련 선택, 면담·규칙 결정, 신뢰·팀워크·피로 표시 |
| 2 | 센터와 포지션 갈등 | 포지션 기준을 정하고 전달하거나 함께 조율 | 갈등 대화, 조율 결정, 다음 달 상태에 반영 |
| 3 | 말투와 습관의 충돌·쇼케이스 리허설 | 공개 질책을 중단시키고 신입을 달래거나 팀 면담 | 캐릭터 반응, 팀워크·피로와 해결 결과 |
| 4 | 쇼케이스 고정 사건 | 무대 실수 직후 신입과 팀 수습, 격려·현장 대응 | 고정 사건 안내, 대응 선택, 성공·실패 결과 |
| 5 | 음원 성적과 첫 음악방송 | 좋은 성과의 A트랙은 홍보 예산 배분, 부진한 B트랙은 저예산 홍보와 자신감 회복 | 이전 결과에 따라 설명·활동 변경, 팬·인지도·자금 변화 |
| 6 | 반기 결산과 신입 개별 활동 제안 | 비서 보고 확인, 신입 예능 출연 여부와 준비 방향 결정 | 누적 상태·훈련 기록, 출연 결정, 데모 마무리 |

### 원안 수치와 판정의 해석

- 초기 팀워크 40·피로도 20이 명시되어 있다.
- 2개월차에는 팀워크 42 이상, 3개월차에는 피로도 60 미만·팀워크 40 이상이라는 기준이 있다.
- 4개월차에는 신입 신뢰·팀워크·이슈 통제 조건이 있으나 신뢰 임계값과 이슈 통제 계산식이 충분히 정의되어 있지 않다.
- 5개월차에는 A/B트랙별 성과와 홍보 결과 수치가 있으나, 어떤 사용자 입력을 성공으로 볼지 세부 기준을 정해야 한다.
- 6개월차에는 예능 준비에 따른 판정이 있으나, '능력치가 반만큼 오른 상태'를 수치로 정의해야 한다.
- 원안의 분기 화살표에 적힌 값은 누적 경로 예시다. 모든 경로를 고정 수치로 덮어쓰는 방식으로 구현하지 않는다.
- 세부 계산식·미정 수치·거절 결과는 임의로 확정하지 않는다. 데모용 규칙을 보완하면 원안과 구분해 기록한다.

## 5. 데모 대화와 실제 AI의 경계 — 구현 제안

- 목표 연결은 프론트 → 백엔드 → 데모/실제 AI 응답 → 저장 → 프론트다. 현재 새 면담은 프론트 내부 데모 어댑터와 브라우저 저장으로 먼저 구현했다. 기존 축약 게임은 백엔드 경로를 유지한다.
- 연습생별 소개·고민·질문 예시와 응답을 준비하고, 실제 AI가 연결된 것처럼 표시하지 않는다.
- 정해진 데모 표현 외 자유 입력은 일반 대화 응답 또는 지원 범위 안내로 처리한다. 자유 입력만으로 임의의 활동·수치 변경이 확정되지 않도록 한다.
- 후보를 전환해도 같은 플레이 안에서 후보별 대화 기록을 유지한다. 최종 선택은 별도의 확정 동작으로 처리한다.
- 사용자가 세 명 완료 필수·자유 순서·수동 마무리·비서의 자동 마무리를 확정했다. 현재 최소 1회 대화 후 수동 종료, 8회 후 자동 종료를 기본값으로 구현했다. 횟수는 원안 확정 수치가 아니다.
- 실제 AI 연결 때는 상대 ID·현재 단계·사용자 입력·최근 대화·공개 상태를 전달하고 발화자·대사·감정을 받도록 계약을 정한다. 이는 제안이며 아직 API 명세가 아니다.
- 현재 `analyze()`·`generate()`를 확장할지 별도 AI 서버를 호출할지는 팀원과 결정한다. 게임 결과와 저장은 백엔드가 담당한다.

## 6. 현재 코드와의 차이

| 현재 구현 | 필요한 작업 |
|---|---|
| 새 UI에서 도입·세 후보 면담·영입 확인 | 브라우저 데모를 서버 저장·월별 운영 게임에 연결 |
| 새 면담 상대와 영입 후보 분리·후보별 브라우저 기록 | 서버에서 동일 상태와 검증을 관리 |
| 1 → 6 → 13 → 24개월차 | 1~6개월차를 순서대로 구성하고 Part 2 종료 지점 추가 |
| 1개월차 예능 훈련·휴식 위주 | 원안의 훈련·멤버 갈등·쇼케이스·홍보 활동 추가 |
| 발화자는 `secretary` / `newcomer` | 면담 후보와 기존 멤버를 어떤 ID·표현으로 다룰지 정하고 AI 계약과 함께 수정 |
| 팀워크·피로·신뢰·인지도·팬·자금 | 신입 능력치·면담 진행·월별 결과 등 필요한 상태 확장 |
| SQLite 저장, 중복 요청 방지, 상태 버전 검사 | 기존 기능을 유지하면서 새 상태와 호환성 정책 반영 |

기존의 13·24개월차 콘텐츠를 이번 계획만으로 삭제하지 않는다. 새 콘텐츠 버전과 기존 저장의 처리 방식을 구현 시 명시한다.

## 7. 개발 순서와 완료 기준 — 구현 제안

1. 데모 콘텐츠와 미정 조건 정리: 후보 소개·면담 예시, 각 월의 활동·최종 결정·결과를 확인한다.
2. 화면 배치: 디자인 참고 자료와 토큰을 정한 뒤 공통 화면과 면담 화면을 만든다.
3. 면담 흐름: 후보별 대화·전환·완료 표시와 한 명 영입 확정을 연결한다.
4. 월별 흐름: 1~6개월차 콘텐츠와 결정·상태·분기를 백엔드와 연결한다.
5. 시연 점검: 정상 진행과 실패 경로, 저장·복원·재시도를 확인한다.

완료 기준:

- [ ] 시작부터 Part 2 마무리까지 막힘 없이 진행된다.
- [ ] 세 후보를 면담하고 한 명만 영입할 수 있다.
- [ ] 상대를 전환해도 대화가 섞이거나 사라지지 않는다.
- [ ] 각 월의 사건·과제·결정과 결과가 표시되고 다음 월로 진행된다.
- [ ] 5개월차 A/B트랙과 앞선 월의 성공·실패 차이를 확인할 수 있다.
- [ ] 6개월차 결정 후 7개월차로 넘어가지 않고 데모 완료를 알린다.
- [ ] 한글 조합 중 Enter 오전송, 중복 전송, 긴 대화, 응답 대기·오류·재시도를 확인한다.
- [ ] 새로고침 후 현재 단계·선택·대화가 복원된다.
- [ ] 프론트 빌드와 관련 백엔드 테스트를 통과한다. 실제 유료 AI 호출은 필수가 아니다.

## 8. 구현 전에 정할 내용

| 항목 | 현재 상태 / 제안 |
|---|---|
| 후보 이름·설정·이미지 | 노션의 여울·이도·사야 설정 확인. 코드 A/B/C와의 ID 대응·소개 공개 범위·이미지 자산은 미정 |
