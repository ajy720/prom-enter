# 13~24개월 서버 연결 시 보존 기준

작성·사용자 확인: 2026-11-11. 사용자가 전달한 월별 흐름과 [PR #38](https://github.com/ajy720/prom-enter/pull/38) 본문, 최종 프런트 데모를 대조하고 차이를 확인받아 작성했다. 최초 제안보다 **최종 데모 규칙·수익 밸런스**를 우선한다. [7~12개월 보존 기준](part3-server-integration-rules.md)에서 이어지는 협업 문서다.

이 문서는 서버 연결 후 유지할 플레이 경험과 판정의 요구사항이다. 현재 서버가 이를 모두 구현했다는 뜻은 아니다. 이번 작업은 문서 작성이며 API·DB·AI provider·게임 코드는 변경하지 않는다.

## 적용 범위·변경 전 확인

- 기준 구현은 PR #38 병합 커밋 `0c5689b215f92efdac367b6532676f37e0f91e9b`의 Part 4 구현과 현재 기준 커밋 `7a655b33ee8b93d6e9cfa9e52c4558cf6268b49c`까지의 공통 화면 보완이다. [PartFour.tsx](../../frontend/src/PartFour.tsx), [part4State.ts](../../frontend/src/part4State.ts), [part4Content.ts](../../frontend/src/part4Content.ts), [part4.css](../../frontend/src/part4.css) 및 공통 컴포넌트·스타일·이미지를 함께 확인한다. 검토 URL은 `/?part4Demo=1`이다.
- [최종 데모 기록](part4-frontend-demo.md)의 최종 규칙·수익 밸런스·서버와의 차이를 참고한다. 초기 [제안](../planning/part4-frontend-proposal.md)과 사용자의 초기 월별 초안에 미정·다른 조건이 있어도, 이번에 확인한 아래 기준으로 작성한다. 이후 코드 변경이 이 기준을 자동으로 바꾸지는 않는다.
- **서버 연결은 기존 프런트의 흐름과 확정 규칙에 맞춰 서버를 연결·변경하는 작업이다.** 기존 서버가 다르게 동작한다고 프런트의 단계·선택지·판정·연출을 축소하거나 서버 화면으로 대체하지 않는다.
- **서버를 수정하기 전에**, 해당 월의 기존 서버 조건·데모 조건·변경할 수치와 분기·API/DB 및 기존 저장에 미치는 영향을 사용자에게 제시하고 확인받는다. 이 문서 작성 승인을 서버 구현 전체의 사전 승인으로 간주하지 않는다. 같은 변경안에 대해 받은 승인을 반복해서 요청할 필요는 없다.
- 데모와 문서가 다르거나 서버 연결 중 ID·화자·판정·AI 평가·수익·저장 이관 등 애매한 부분이 있으면 임의로 추정하지 않는다. 차이와 가능한 처리 방식을 사용자에게 먼저 확인받고 해당 부분을 변경한다. 확인과 무관한 작업은 계속할 수 있다.
- 화면 구성·진행 순서·선택지·필수 면담·전환 조건·수치 기준 자체를 바꿔야 할 때도 이유와 전후 차이를 제시하고 먼저 확인받는다. 프런트에서 서버 검증을 우회하거나 결과를 임의 확정하는 방식으로 해결하지 않는다.

## 공통 화면·진행·진입 규칙

- 13~22개월과 24개월은 대표실이다. 23개월은 무대의 시상식 나레이션 두 장면 뒤 대표실로 전환한다. 사용자 제공 배경·인물·논란 사진, 인물 크기·배치·색상·버튼·입력창·PC/모바일 구성을 보존한다. [디자인 기준](../design/ui-direction.md)을 함께 따른다.
- 나레이션은 `NarrationScene`, 인물·대화는 기존 `PhotoSlot`과 흰 대사 영역, 채팅은 `ChatComposer`, 선택 확인·기록은 기존 `Modal`을 사용한다. 나레이션·면담 중 자금/기간 캡슐은 숨기고 필요한 운영 화면은 `ResourceStatus`를 유지한다.
- 사용자가 다음 버튼으로 상황·안내를 읽고 면담·조사·선택으로 진행한다. 선택 초안은 효과가 없고, 확인 창에서 확정할 때만 판정·수치·저장이 반영된다. 결과를 읽은 뒤 다음 달로 이동한다. 23개월은 정해진 장면을 읽고 24개월로 넘어가며 별도의 활동 선택이 없다.
- 13개월 신입과 19개월 양쪽 루트의 네 멤버는 각각 사용자 발화 기준 1~8회 면담한다. 20개월 해외는 백하연과 3~7회 대화한다. 첫 인사·대상 전환·질문 예시 선택은 횟수에 포함하지 않는다. 예시는 초안만 채우며 사용자가 전송한다. 면담·대화 자체는 스텟을 바꾸지 않는다.
- 실제 선발 신입·스텟을 12개월에서 이어받는다. 예시 진입은 예시임을 표시하며 실제 저장을 대체하지 않는다. 목표는 영입 후 월별 활동 안내 다음에 국민 그룹/글로벌 스타/음악력 증명 중 선택한다. 목표가 없는 이전 저장은 Part 4 진입 전 한 번 선택하고 기본값을 임의 지정하지 않는다.
- 피로·팀워크·신뢰·인지도는 0~100, 팬·자금은 0 이상으로 제한한다. 자금은 원 단위 정수로 계산한다. 단계별 변화는 실제 적용량을 합쳐 표시하며 중복 적용하지 않는다.
- 해외 팬 증가분은 총팬에 포함된 부분집합이다. 총팬과 다시 합산하지 않는다. 이전 저장의 지역별 팬은 추정하지 않고 ‘이전 지역별 수치 미집계’로 표시한다. 보컬·댄스는 이번 구간 신입 성장분을 별도 보존하고 초기 능력치로 오인하지 않는다.

장소: 대표실.

1. ‘띠링’ 알림을 나레이션으로 제시한다.
2. 사용자가 게시물을 확인하면 선택 신입의 논란 글 원본 사진을 표시한다.
3. 백하연이 확인되지 않은 SNS 주장임을 설명하고 여론 확인·본인 면담·기록 조사를 안내한다.

장소: 대표실.

1. 13개월 완전 성공이면 위기를 넘긴 팀의 단체 광고 계약, 부분 성공이면 신입을 제외한 기존 멤버 한 명을 모델로 하는 조건부 계약을 나레이션으로 제시한다.
2. 백하연이 남은 이미지 손상과 회복 콘텐츠의 필요성을 설명한다.
3. 안내 후 기부 프로젝트 / 봉사활동 자체 콘텐츠 / 팬과 함께하는 공익 캠페인 중 하나를 선택·확정한다.
4. **모든 선택은 성공**이다. 자금 +1억·인지도 +5·팬 +1만을 한 번 적용하고 결과를 표시한다. 별도 광고 멤버 선택이나 추가 광고 보상을 만들지 않는다.

## 15개월 · 단체 고정 예능

장소: 대표실.

1. 이미지 회복 이후 관심이 늘어난 나레이션과 백하연의 단체 고정 예능 제안 안내를 읽는다.
2. 단체 예능 출연 / 자체 콘텐츠 유지 중 선택·확정한다.
3. 단체 예능은 **인지도 60 이상·팀워크 60 이상 모두 충족**하면 성공한다. 신입의 예능 능력치 조건으로 되돌리지 않는다.

| 선택·결과 | 효과 |
|---|---|
| 단체 예능 성공 | 인지도 +10·팬 +3만·출연료 +5천만 원 |
| 단체 예능 실패 | 인지도 −8·팬 −1만 |
| 자체 콘텐츠 유지 | 성패 없는 선택 완료(`neutral`), 수치 변화 없음 |

## 16개월 · 팬미팅 규모와 가격

장소: 대표실.

1. 팬들의 만남 요청을 나레이션과 백하연 안내로 제시한다.
2. 규모 **1천/5천/1만5천 석**과 가격 **4만/7만/10만 원**을 각각 선택한다. 예상 관객과 성공 예상 순수익을 표시한다.
3. 확인·확정 시 다음을 확정 전 스텟으로 계산한다.

`예상 관객 = 내림(팬 × (20 + 인지도) × 40,000 ÷ (100 × 티켓 가격))`

`성공 조건 = 선택 좌석 ≤ max(1,000, 예상 관객)`

`성공 순수익 = 내림(min(선택 좌석, 예상 관객) × 티켓 가격 × 40%)`

4. 성공은 팬 +5만·팀워크 +5·계산한 순수익, 실패는 자금 −1억이다. 팬 증가 전 수요로 수익을 계산한다. 최소 1천 석 허용으로 성공하더라도 가상의 매진 수익을 지급하지 않는다.

## 17개월 · 몰리는 스케줄

장소: 대표실.

1. 팬미팅 성공이면 성공적으로 마친 나레이션, 실패이면 공연은 마쳤지만 수요 예측으로 자본 손실이 발생한 나레이션을 표시한다.
2. 백하연이 몰린 일정·멤버 피로·신입 연습 부족과 무대 완성도를 설명한다.
3. **겹치는 일정 거절·휴식일 확보 / 필수 일정만 유지 / 전체 일정 강행** 중 선택·확정한다.
4. 피로 −20 / −10 / +5를 먼저 적용하고 범위를 제한한다. 그 뒤 **피로 60 미만이며 강행이 아니면 성공**한다.
5. 성공은 피로 −15·팀워크 +5·신입 댄스 성장 +1, 실패는 피로 +20·인지도 −5다. 최초 일정 조정과 결과 효과의 실제 순변화를 함께 표시한다.

## 18개월 · 일본 프로모션과 루트 선택

장소: 대표실.

1. 전월 성공이면 휴식·회복, 실패이면 병원 방문·목 컨디션 악화의 나레이션을 표시한다.
2. 백하연이 일본 중견 유통사의 제안을 설명한다. 평판은 ‘기존 정산 지연 사례는 확인되지 않음’, 조건은 현지 TV 2회·현지어 곡 1곡·쇼케이스 공동 부담, 우리 투자금 1억·정산 대상 순수익 우리 60%/유통사 40%다.
3. 수락 / 거절을 선택·확정한다. 투자금 1억 미만이면 수락을 막고 부족 상태를 표시한다.
4. 수락은 해외 루트, 총팬 +5만·그중 해외 팬 +5만·자금 −1억이다. 거절은 국내 루트이며 수치 변화가 없다. 두 선택 모두 별도 계약 성패가 없는 선택 완료다.
5. 평판·배분 비율은 안내 내용이다. 이 비율을 근거로 이후 정해진 활동 수익을 다시 나누거나 추가 비용을 임의 부과하지 않는다.

## 19개월 · 루트별 활동 준비

장소: 대표실. **두 루트 모두 네 멤버 각각 1~8회 면담을 먼저 진행**하고 마무리한 뒤 활동을 선택한다.

### 해외 루트

1. 일본 진출 확정 나레이션 → 백하연의 언어 부담 안내 → 네 멤버 면담 순서다. 신입이 사야면 언어 부담이 없고 다른 멤버를 도울 수 있다고 답한다. 이도·여울 선발 시 백하연 안내와 면담 문맥에 미선발 사야의 언어 특성을 넣지 않는다(2026-11-11 사용자 확인).
2. 어학 훈련 실시/미실시와 현지 감성/팀 정체성 유지 콘셉트를 각각 선택·확정한다.

| 항목 | 효과 |
|---|---|
| 어학 훈련 실시 | 자금 −2천만·피로 +5. 자금 부족 시 선택 불가 |
| 어학 훈련 미실시 | 변화 없음 |
| 현지 감성 | 인지도 +5·총팬 +1만·그중 해외 팬 +1만 |
| 팀 정체성 유지 | 팀워크 +5·총팬 +5천 |

3. 훈련과 콘셉트 효과를 합쳐 적용하고 **성패 없이** 20개월로 진행한다. 팀 정체성의 팬 증가를 해외 팬으로 임의 분류하지 않는다.

### 국내 루트

1. 국내 팬과의 만남을 늘린 나레이션 → 백하연의 도하 생일카페 안내 → 네 멤버 면담 순서다.
2. 모든 생일카페 방문 / 일부 방문 / 미방문 중 선택·확정한다.
3. 전체·일부 방문은 모두 성공하여 팀워크 +5·인지도 +5·피로 +5다. 미방문은 실패하여 피로 −10·인지도 −5다.

## 20개월 · 해외 루머 대응 또는 국내 라디오

장소: 대표실.

### 해외 루트

1. 현지 쇼케이스 성공과 국내 대형 기획사 ‘바이프’의 루머·바이럴 상황을 나레이션으로 제시한다. 별도 쇼케이스 성공 판정·수익은 추가하지 않는다.
2. 백하연 안내 후 **최소 3회·최대 7회** 대화한다. 마지막으로 확인한 명확한 실행 지침과 그 근거를 기록한다.
3. 인용·질문·부정·단순 감정 표현을 감정적 실행 지시로 취급하지 않는다. 3회 이상 명확한 지침이 있으면 마무리할 수 있다. 모호하면 7회까지 대화하고, 여전히 모호한 경우 선택 화면에서 **사실·공식 절차 중심 / 감정적 맞대응 실행**을 직접 확인한다. 임의로 어느 쪽도 기본 선택하지 않는다.
4. 대화 마무리 후 법적 대응 / 팩트 해명 / 무대응을 선택·확정한다.
5. 사실·절차 중심 지침이며 법적 또는 팩트 대응이면 성공하여 인지도 −2·팬 +1만·팀워크 +5다. 감정적 실행 지침 또는 무대응이면 실패하여 인지도 −10·팬 −3만·피로 +15다. 성공의 인지도 감소도 그대로 적용한다.

현재 문장 평가는 제한된 데모 규칙이다. 실제 AI로 옮길 때도 위 구분·횟수·모호한 지침 확인을 보존하며, 모델 평가 기준과 서버 검증 방식은 구현 전에 사용자에게 확인받는다. 데모 정규식 결과를 실제 AI 검증 결과로 설명하지 않는다.

### 국내 루트

1. 생일카페 결과와 이미 적용된 수치 변화를 나레이션으로 설명한다. 이 설명 때문에 19개월 효과를 다시 적용하지 않는다.
2. 백하연이 인기 라디오의 즉석 라이브와 콘서트 홍보를 안내한다.
3. 대표곡 / 팬송 / 어쿠스틱 편곡 중 하나와 홍보 멘트를 입력·확정한다. 공백만 있는 멘트는 불가하며 공백·줄바꿈 포함 최대 500자다. 현재 길이는 JavaScript 문자열 길이 기준이다.
4. 직접적인 팬 모욕·관람 거부 지시는 실패 경고를 표시하고 사용자가 그대로 확정하면 실패한다. 그 외에는 성공한다. 인용·부정 등을 단순 단어 포함만으로 실패시키지 않는다. 실제 평가로의 전환이나 애매한 표현 범위는 먼저 사용자에게 확인받는다.
5. 성공은 인지도 +5·팬 +5천, 실패는 팬 −5천이다. 팀워크 변화와 실패 시 인지도 감소는 없다. 노래 종류만으로 별도 성패를 만들지 않는다.

## 21개월 · 첫 단독 콘서트

장소: 대표실.

1. 해외는 20개월 성공 시 귀국 후 공식 대응으로 논란이 가라앉는 나레이션, 실패 시 나쁜 여론이 남은 나레이션이다. 국내는 라디오 홍보 성공 시 팬 기대, 실패 시 객석에 대한 우려를 제시한다.
2. 이후 두 루트 공통으로 백하연이 콘서트 준비와 조건을 안내한다.
3. 규모·가격·연출비는 각각 자유 선택하지 않고 아래 **세 묶음 패키지** 중 선택·확정한다.

| 패키지 | 좌석 | 가격 | 연출 예산 | 성공 순수익 |
|---|---:|---:|---:|---:|
| 소형 | 3천 | 7만 원 | 3천만 원 | +5억 |
| 중형 | 1만 | 10만 원 | 8천만 원 | +8억 |
| 대형 | 3만 | 15만 원 | 2억 원 | +12억 |

`예상 관객 = 내림(팬 × 30% × 70,000 ÷ 티켓 가격)`

4. 예상 관객≥좌석, 연출비≤현재 자금의 20%, 피로<60, **20개월 결과 성공**을 모두 만족해야 성공한다. 전월 조건을 생략하지 않는다.
5. 성공은 팬 +10만·인지도 +10·규모별 순수익, 실패는 자금 −2억·피로 +15·팬 −1만이다. 순수익은 티켓·중계·협찬·굿즈 및 연출비를 포함한 간소화 정산이므로 연출비나 티켓 수입을 다시 가감하지 않는다. 실패는 성공 수익 없이 정해진 손실만 적용한다.

## 22개월 · 목표에 맞춘 마지막 앨범

장소: 대표실.

1. 콘서트 성공이면 성공 나레이션, 실패이면 빈 객석·컨디션·예산·홍보 등 준비의 아쉬움을 설명한다. 좌석이 수요보다 적다는 이유만으로 새로운 실패 조건을 추가하지 않는다.
2. 백하연이 처음 선택한 2년 차 목표를 상기시키고 계약 만료 전 마지막 앨범을 안내한다.
3. 콘셉트, 타이틀곡 유형, 제작비·홍보비·예비비를 각각 입력·선택한다. 목표를 이 단계에서 임의 변경하지 않는다. 예산 입력과 잔액 갱신 중에는 스크롤·입력 포커스를 유지한다.
4. 세 예산은 0 이상의 원 단위 정수이며 합계가 **현재 자금 전액**과 같아야 확정할 수 있다. 입력 중 `현재 자금 − 제작비 − 홍보비 − 예비비`인 **남은 배분 가능 자금**을 표시하고 초과 배분은 음수로 보여준다.

| 목표 | 필요한 콘셉트 / 곡 | 제작 최소 | 홍보 최소 | 예비비 최소 |
|---|---|---:|---:|---:|
| 국민 그룹 | 대중 친화 / 밝은 팝 | 30% | 30% | 10% |
| 글로벌 스타 | 글로벌 / 댄스 팝 | 25% | 40% | 10% |
| 음악력 증명 | 라이브 / 보컬 중심 | 50% | 20% | 10% |

5. 비율은 **지출 전 현재 자금** 기준이다. 자금>0, 목표에 맞는 콘셉트·곡, 위 최소 비율, 팀워크≥80·피로<50을 모두 충족해야 성공한다.
6. 성패와 무관하게 제작·홍보비만 먼저 지출하며 예비비는 잔액으로 남긴다. 성공은 인지도 +10·팬 +10만·수익 +10억, 실패는 인지도 +3·팬 +2만·추가 손실 −1억이다. 실패의 최종 자금도 최소 0으로 제한한다. 초기 제안의 성공 수익 +15억이나 서버의 잔액 3억 조건으로 되돌리지 않는다.

## 23개월 · 연말 시상식과 감사 인사

장소: 무대 → 대표실.

1. 22개월 성공이면 커리어 하이, 실패이면 아쉬움을 담은 앨범 활동 회고와 시상식 후보 참석을 나레이션으로 표시한다.
2. 23개월 진입 시 누적 스텟으로 수상 등급을 정하고 무대 나레이션으로 공개한다.

| 조건 | 결과 |
|---|---|

4. **실제 선발 신입 → 리안 → 도하 → 세인** 순서로 각자 감사 인사를 한다. 이후 백하연이 재계약 의향을 묻고 사용자가 24개월로 진행한다. 인사를 단체 요약이나 사용자 자유문 하나로 대체하지 않는다.

## 저장·API·실제 AI 연결

- API 호출·응답 변환·서버 상태 연결을 허용하되 기존 화면과 월별 흐름을 유지한다. 최종 수치·성패·분기·결말·영구 저장은 서버가 확정한다. 필요한 모델 평가도 서버 검증을 거친다.
- 신입 ID·기존 멤버 ID·백하연 화자를 정확히 매핑한다. 리안=`dahyun`, 도하=`haram`, 세인=`yuna`이며 신입은 실제 프로필을 사용한다. 서버 계약과 다르면 명세에 명시하고 애매한 대응은 먼저 확인받는다.
- 현재 독립 저장은 `prom-part4-demo-v1:{game_id 또는 sample}`, 통합 브라우저 저장은 `prom-playthrough-v2:{game_id}`의 `part4`·`stage: 'part4'`, 목표는 `prom-game-goal-v1:{game_id}`다. 전달용 `prom-part4-source-v1`·`prom-part4-server-source-v1`는 세션 저장이다. 로컬 키는 현재 구현 설명이며 서버 DB 형식을 강제하지 않는다.
- 기존 브라우저 저장과 서버 저장을 임의 혼합·덮어쓰기·자동 업로드하지 않는다. 이관 정책, 이미 13개월 이후인 서버 저장의 처리, 이전 성장·지역별 팬 누락 등은 먼저 확인받는다. 현재 서버→데모 분기는 12개월 직후 사용자가 명시적으로 선택하는 별도 경로다.
- 선택 초안·대화·면담 횟수·단서·지침 및 근거·확인 지침·목표·루트·결과·정산·성장·수상·의향·흰 화면·결말을 저장·복원한다. 저장 성공 뒤 화면을 갱신하고, 다중 화면의 진행 충돌은 덮어쓰지 않는다. 손상 저장은 원본을 보존하고 오류를 표시한다.
- 요청 재시도·새로고침·중복 전송으로 대화 횟수·단서·비용·보상·월 이동을 중복 적용하지 않는다. 처리 중과 미해결 요청은 잠금을 유지하고 오류·재시도를 표시한다. 서버 오류를 데모 성공으로 숨기지 않으며 키 없는 명시적 데모 경로를 유지한다.
- 요청·응답·상태·ID·화자·표시 순서·오류·저장 계약 변경은 [프런트 연결 명세](frontend-integration.md)와 [types.ts](../../frontend/src/types.ts)에 함께 반영한다. 지원/미구현, 변경일, 웹 담당 수정과 호환·적용 순서를 남긴다. 기존 로컬 `Part4Save`를 이미 지원되는 서버 응답으로 설명하지 않는다.
