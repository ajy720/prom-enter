# 인물별 지식과 공개 조건

[문서 안내](../README.md)

각 정보의 내용, 누가 아는지, 누구에게 말할 수 있는지, 언제 어떤 경로로 알게 됐는지를 분리합니다. 권한은 서버가 검사하며 모델이 해금하거나 사실을 확정하지 않습니다.

## 자료와 상태

| 자료형 | 역할 |
|---|---|
| `KnowledgeRecord` | 정보 원본: 대상 인물, 내용, 종류, 출처, 초기 인지자, 공개 정책 |
| `KnowledgeGrant` | 플레이 중 정보 습득: 인지자, 사건, 원본 턴, 관찰/보고/전달 경로 |
| `DisclosureGrant` | 발화자와 청중을 지정한 공개 허가. 허가 자체가 전달 완료를 뜻하지 않음 |

`subject_id`는 정보의 대상입니다. 기존 `character_id`는 호환을 위해 남겼습니다. `initial_known_by`는 처음부터 아는 인물입니다. `kind=report`, `certainty=reported`는 사용자의 발언을 들었다는 뜻이며 내용이 참이라는 뜻이 아닙니다. 서버에서 확정한 사건 결과만 `fact` / `confirmed`로 기록합니다.

기획 원문은 `characters/sources/`와 `characters/archive/`에 보존하고, 현재 사용하는 Markdown 7개는 `characters/` 바로 아래에 둡니다. [이름 변경과 원문 우선순위](../../characters/README.md)를 따릅니다. 컴파일된 `characters.json`에는 현재 자료와 초기 인지 정책의 해시·출처를 보존합니다.

## 초기 인지 범위 편집

`characters/knowledge-policy.json`에서 **대상 인물 → 그 성향을 알고 시작하는 인물**을 수정합니다.

```json
{
  "hyerin": ["hyerin", "baek_hayeon"]
}
```

이는 이도의 표면 성향을 이도와 백하연이 알고 시작한다는 정책입니다. 데모 기본값은 백하연은 모두의 성향을, 기존 데뷔조는 서로의 성향을, 신입은 자신의 성향을 압니다. 이름·나이·포지션·후보 구분은 모두가 압니다. 이 인지 범위는 원문에서 자동으로 입증된 관계가 아니라 조정 가능한 초기 정책입니다.

성향 문구는 원문 3절의 첫 네 문장을 그대로 가져옵니다. 내면·과거사·미래 사건은 요약에 넣지 않습니다. 수정 후 아래 명령을 실행하고 서버·콘솔을 재시작합니다.

```sh
backend/.venv/bin/python scripts/compile_characters.py
```

`shareable_past`에는 본인이 면담에서 이야기할 수 있는 원문 8절의 문단을 인물별로 지정합니다. 문구가 원문과 달라지면 컴파일이 실패하므로 원문 수정 시 공개 범위도 다시 확인합니다. 예를 들어 이도의 중학교 독창 무대 경험, 여울의 학교 축제·독학·오디션 경험은 말할 수 있습니다. 백하연과 기존 멤버는 일반 경력·학교 공연·연습 경험을 추렸으며, 죄책감이나 감춰 둔 사정은 공개하지 않습니다.

승인된 문단은 `profile:{id}:shareable_past`라는 별도 `ordinary` 자료로 컴파일합니다. 처음부터 아는 인물은 본인뿐이며, 간접적인 꼬리 질문에도 답할 수 있도록 본인 대사 문맥에 항상 넣습니다. 전체 과거사 `:past`와 핵심 비밀 `:secret`의 기존 ID·잠금·공개 허가는 유지합니다. 다른 인물이 같은 내용을 자동으로 아는 것은 아닙니다.

## 공개 정책

| `disclosure` | 처리 |
|---|---|
| `ordinary` | 알고 있는 인물이 다른 청중에게 설명 가능. 모두가 이미 아는 것은 아님 |
| `confidential` | 현재 청중이 이미 아는 정보이거나, 해당 청중에 대한 공개 허가가 있을 때만 전달 |
| `sealed` | 발화자·청중에 대한 명시적인 공개 허가가 있어야 원문 전달 |

잠긴 비밀은 본인이 알고 있더라도 허가 전에는 모델 요청에 원문·제목·ID를 넣지 않습니다. 보호된 내용을 추측하지 않도록 안내하되, 제공된 경험이나 일상 이야기까지 일괄적으로 회피시키지 않습니다. 기존 `visibility=public`은 보편적인 인지 권한을 뜻하지 않으며, `locked`는 `sealed`로 해석합니다.

기존 `revealed_knowledge_ids`는 해당 자료의 주인공이 플레이어에게 말할 수 있다는 과거 의미만 유지합니다. 백하연 등 다른 인물까지 자동으로 알게 하지 않습니다.

## 사건과 대화에서 습득

- 서버가 확정한 사건 결과·증거는 그 장면의 관찰자에게 기록합니다.
- 사용자 발언은 실제 청중에게만 미검증 보고로 기록합니다. 질문이나 주장을 사실로 요약하지 않습니다.
- NPC 대사는 인용 유무와 관계없이 검증 후 **실제로 말한 문장만** 출처가 있는 보고로 기록하여 청중에게 전달합니다. 인용 없는 일상 경험도 이후 관련 질문에 검색할 수 있습니다. 자료 ID를 인용했다는 이유로 원문 전체를 알게 하지 않습니다. 다른 인물이 다음 턴에 참고할 수 있지만 보고를 확정 사실로 승격하지 않습니다. 원본 사실의 습득은 서버 사건에서 명시적으로 부여합니다.
- 발언 기록은 실제 대화 청중 범위의 `confidential` 보고입니다. 공개 자료를 하나 인용했다고 대사 전체의 사적인 부분까지 다른 청중에게 전할 수 있게 하지 않습니다.
- 공개 허가는 내용을 들었다는 뜻이 아닙니다. 실제 발화 전에는 청중의 지식을 추가하지 않습니다.
- 같은 요청의 재시도는 지식·효과를 중복 생성하지 않습니다. 생성·검증·DB 충돌이 실패하면 지식 변경도 저장하지 않습니다.

향후 작성자가 동의·발견 사건을 만들 때 `ai/knowledge.py`의 서버 함수를 연결합니다. 아래는 연결 예시이며 현재 시나리오의 새 사건을 뜻하지 않습니다.

```python
grant_knowledge(state, knowledge_id, ["baek_hayeon"],
                event_id=event_id, turn_id=turn_id, method="report")
permit_disclosure(state, knowledge_id, "baek_hayeon", ["player"],
                  event_id=event_id, turn_id=turn_id)
```

실제 시나리오의 핵심 비밀을 공개하는 새 사건이나 동의 조건은 임의로 작성하지 않았습니다. 일반 자유 발언으로 공개 허가를 자동 발급하지 않습니다.

## 구체적인 답변과 자유 창작

경험·이유·시기를 물으면 제공된 경험과 이전 발언을 우선 사용해 상황·사건·감정을 구체적으로 답합니다. 수줍음과 낮은 신뢰는 말투와 망설임으로 표현하고, 이미 말할 수 있는 내용을 정보 부족이나 동의 문제로 회피하지 않습니다. 정확한 날짜가 없으면 설정이 뒷받침하는 시기까지만 말합니다.

설정이 비어 있는 부분에는 성격·이전 발언과 일치하는 본인의 작은 일상 경험·습관·감각 묘사를 창작할 수 있습니다. 가족관계·트라우마·질병·핵심 비밀·주요 갈등·다른 인물의 행동·공식 경력·게임 수치·증거·활동 완료·미래 사건은 창작하지 않습니다. 실제 설정을 함께 사용하면 그 자료만 인용하며, 전적으로 창작한 일상 경험에 가짜 자료 ID를 붙이지 않습니다.

창작 경험도 대사 원문을 `report` / `reported`로 저장하며 서버 사실이나 보상으로 승격하지 않습니다. 최근 대화·관련 대화·관련 발언 검색을 통해 이어 쓰고 청중 범위를 유지합니다. 모든 과거 발언이 매번 문맥에 들어가는 것은 아니므로 장기 일관성과 창작 경계 준수는 실제 모델 평가가 필요합니다.

## 대화 문맥과 청중

모든 대사는 화자별로 별도 생성합니다. `allowed_speakers`는 발화자, `audience_ids`는 실제 청중의 정식 ID, `output_audience`는 저장 기록의 역할 목록입니다. 공개 발언을 두 인물이 함께 듣는 경우 모델 호출을 나눴다는 이유로 사적인 발언으로 취급하지 않습니다. 반대로 1:1 발언·개인 기억은 다음 공개 대화의 모델 문맥에서 제외합니다.

상대 전환 원문은 이전 방의 청중에게만 보고로 남고 새 상대에게 전달하지 않습니다. 순차 생성 중 후반 호출이 실패하면 앞선 호출 비용이 발생할 수 있지만 게임 상태와 지식은 저장하지 않습니다.

HTTP 요청·응답과 상대 전환·저장 호환은 [프런트엔드 연결 명세](frontend-integration.md#상대와-화자), 콘솔 명령과 기록 저장은 [캐릭터 콘솔](../guides/character-console.md)를 따릅니다. 콘솔의 인물별 습득 상태는 실행 중 유지되며 게임에서는 SQLite에 저장됩니다.

## 보장 범위와 평가

서버는 자료 접근·공개 정책·참조 ID·실제 청중·저장 원자성을 검사합니다. 창작 허용 범위는 프롬프트 지침이며, 모델이 범위를 벗어나 추측하는 현상까지 의미적으로 완전히 검출하지는 못합니다. 정확한 미묘한 표현·추측 억제·장기 일관성은 실제 모델 평가가 계속 필요합니다. 대사를 기록해도 그 내용에서 새로운 확정 사실을 자동 추출하지 않습니다.

테스트는 인물별 초기 인지, 비밀 원문 차단, 공개 허가와 전달의 구분, 보고와 사실의 구분, 1:1 기록의 공개 문맥 유출 방지, 습득 출처, 중복 요청·실패 시 원복과 기존 저장 호환을 확인합니다.
