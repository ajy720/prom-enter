# 아키텍처와 코드 안내

[문서 안내](../README.md) · [AI 모듈](ai-module.md) · [프런트엔드 연결 명세](frontend-integration.md)

## 구성과 책임

React·TypeScript 프런트는 입력과 상태 표시를 담당하고, FastAPI 백엔드는 AI 호출·게임 규칙·SQLite 저장을 담당합니다. API 키와 비공개 지식은 서버에서 관리합니다.

| 영역 | 책임 |
|---|---|
| 프런트 | 사용자 입력, 서버 응답 표시, 처리 중 입력 제어, 같은 요청 재시도 |
| AI | 자연어 해석, 사건 기준 평가, 인물별 문맥 구성, 대사 생성과 출력 검증 |
| 게임 서버 | 허용 행동·청중·수치·사건·엔딩 최종 확정 |
| 저장소 | 소유자 분리, 상태·턴·요청 기록, 버전 검사와 원자적 저장 |

## 한 턴의 처리 흐름

서버가 소유자·요청 ID·상태 버전을 확인하고, 현재 저장 상태에서 AI 문맥을 구성합니다. 자유 입력은 모델이 해석하고 선택지 입력은 허용 행동을 직접 사용합니다. 서버가 행동 결과를 계산한 뒤 처리 후 상태로 화자별 대사를 생성·검증합니다. 모든 단계가 성공하면 상태와 턴을 함께 저장해 응답합니다.

명시적 대화 상대 변경은 모델 없이 서버에서 처리합니다. 자연어 전환은 의도를 해석한 뒤 같은 전환 경로를 사용하며, 사건 도입도 서버가 구성합니다. 요청·응답 형식과 표시 규칙은 [연결 명세](frontend-integration.md), AI 자료형과 검증은 [AI 모듈](ai-module.md)을 기준으로 합니다.

## 코드 위치

| 위치 | 역할 |
|---|---|
| `frontend/src/App.tsx` | 선택·장면·대화·상태·기록 UI 및 재시도 |
| `frontend/src/types.ts` | 프런트의 API 데이터 형식 |
| `backend/app/models.py` | 상태·입력·모델 출력 계약 |
| `backend/app/content/demo.json` | 사건·선택지·결과표·증거·캐릭터·엔딩 조건 |
| `backend/app/ai/context.py` | 현재 사건과 최근 8턴·기억을 분석용/연기용으로 구성 |
| `backend/app/ai/providers.py` | 데모/실제 모델, 프롬프트, 근거 발화·허용 행동 검증 |
| `backend/app/game/engine.py` | 행동 검증, 순수 상태 계산, 스탯 반영, 감정 방향, 엔딩 |
| `backend/app/repository.py` | SQLite, 소유자 확인, 요청 중복 방지, 상태 버전 검사 |
| `backend/app/service.py` | 분석 → 게임 계산 → 표현 → 생성 → 저장 연결 |
| `backend/app/main.py` | HTTP·설정·익명 플레이 쿠키 |

감정 방향은 `backend/app/ai/director.py`, 기억 선택·약속 이행은 `backend/app/ai/memory.py`와 게임 엔진, 최종 엔딩은 엔진의 `determine_ending`이 담당합니다.

## 콘텐츠와 기능 확장

공통 수치·보상은 콘텐츠 데이터에서, 사건별 의미가 다른 판정은 `resolver`에 대응하는 게임 함수에서 수정합니다. 사건 종료는 사용자의 명시적 결정을 사용하고, 반복 가능한 증거·대화 보상은 고유 키로 제어합니다. 사건이 늘어나 resolver 분기가 복잡해지면 개별 함수·모듈로 분리할 수 있습니다.

캐릭터 원문·초기 지식 정책은 [인물 자료](../../characters/README.md), 월별 사건과 미정 조건은 [스토리라인](../../storyline/README.md)을 따릅니다. 원문 프로필의 초기 능력치나 예시 대사가 현재 게임의 실제 상태를 대신하지 않습니다. 프로필 편집과 컴파일은 [AI 모듈](ai-module.md#3-실제-캐릭터-자료), 인지·공개 정책은 [인물별 지식](character-knowledge.md)에 있습니다.

## 저장과 실패 처리

- 서버가 저장 상태를 읽고 계산하며 브라우저가 보낸 수치를 확정 상태로 사용하지 않습니다.
- 같은 요청 ID·내용은 저장된 턴을 재사용하고, 같은 ID에 다른 내용은 409로 거부합니다.
- 상태 버전 검사·상태 변경·턴 기록을 한 트랜잭션으로 처리합니다. 모델 호출 중에는 DB 쓰기 잠금을 잡지 않습니다.
- 분석·생성·검증이 실패하면 상태를 저장하지 않습니다. 실제 모델 실패를 데모 성공으로 바꾸지 않습니다.
- 현재 콘텐츠 버전이 다른 저장은 새 플레이를 요구합니다. 기존 저장의 대화방·도입 등 선택 필드 호환은 [연결 명세](frontend-integration.md#기존-저장과-요청-호환)에 있습니다.

DB 위치·브라우저 소유권·배포 저장 조건은 [설치 및 실행](../guides/setup.md#저장과-운영-조건)을 참고하세요.

## 현재 구현 범위

실행 콘텐츠는 1·6·13·24개월차의 축약 시나리오이며 실제 게임의 전체 콘텐츠는 개발 중입니다. 캐릭터 자료는 7명이지만 게임 대화는 선택 신입과 백하연만 지원하고, 공통 스탯과 감정 태그별 예시 SVG를 사용합니다. 독립 콘솔은 7명 모두와 대화할 수 있습니다.

인물별 관계·능력치, 전체 월별 사건과 엔딩, 장기 기억·사실 정확도·실제 모델 품질·운영 비용 검증의 남은 범위는 [개발 계획](../planning/roadmap.md)에서 관리합니다.
