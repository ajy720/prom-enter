# Part 1–2 최소 프로토타입

2026-11-03. 기존 자유 입력 → 허용 행동 해석 → 서버 판정 → 결과 대사 → 저장 경로를 확장했다. 새 등장인물·화자 역할·인물 간 관계 시스템은 추가하지 않았다. 이도·여울·사야는 이미 있는 후보 자료를 순서대로 사용하며, 화면과 모델 호출의 역할은 계속 `newcomer`와 `secretary`다.

## 실행과 범위

웹의 **후보 면담 시작**으로 이도 → 여울 → 사야를 면담한다. 지원 동기·강점·고민을 자유롭게 물어보고 `면담 마무리하자`로 다음 후보로 넘어간다. 대화 횟수나 주제 개수는 종료 조건이 아니다. 세 면담 후 `이도를 선발해줘`처럼 한 명을 확정한다. 후보가 바뀌어도 과거 턴의 이름과 대화방 기록은 당시 인물을 유지하며, 다른 후보의 면담 발언을 새 후보의 문맥에 전달하지 않는다. 비공개 과거사 해금은 추가하지 않았다.

이후 같은 인물로 1~6개월차를 플레이한다. 리안·도하·세인은 새 대화 상대로 추가하지 않고, 기존 멤버 상황은 사건 설명과 백하연 보고로 전달한다. 6개월차 예능 제안을 결정하면 결과 확인 장면으로 이동하며 `프로토타입 결과 확인해줘`로 시연을 종료한다. 이것은 계약·그룹 활동의 최종 엔딩이 아니다.

함께 대화에서 주요 결정을 자유 입력이나 선택지로 확정한다. 1:1은 기존처럼 대화 전용이며 진행 행동은 함께 대화로 돌아와 실행한다. 여러 행동을 한꺼번에 요청하거나 질문·부정·회상·가정을 말한 경우 확정 행동으로 실행하지 않는다. 실제 모델의 모든 한국어 표현을 검증한 상태는 아니며, 키 없는 데모는 명시된 패턴만 처리한다.

## 이번 프로토타입의 판정표

[최소 기획 결정](../../storyline/06-minimal-decisions.md)을 우선한다. 아래 누락 수치의 보완은 프로토타입용 구현 결정이며 프로듀서의 새 확정 기획을 뜻하지 않는다. 이후 조정 위치는 `backend/app/content/part2.json`과 `backend/app/game/part2.py`다. 복잡한 능력치 상태를 새로 만들지 않고, 훈련 분야는 기존 `training_history`로 기록한다.

| 구간 | 행동·판정 |
|---|---|
| 면담·선발 | 사용자의 면담 종료 → 다음 후보. 세 후보 면담 후 한 명 선발. 같은 달의 모든 주제 완료 판정 없음 |
| 1개월 | 보컬·댄스·예능 중 훈련 한 분야: 4천만 원·피로 +10, 또는 휴식: 피로 −15. 활동 확정 시 팀워크 +5. 준비 없이 마무리도 가능하며 팀워크 −5·피로 +10 |
| 2개월 | 센터 합의 조율은 팀워크 +8 후 판정, 일방 통보는 현재 값으로 판정. 팀워크 42 이상 성공. 공통 피로 +10, 성공 신뢰 +3, 실패 팀워크 −8 |
| 3개월 | 질책 중단·팀 면담은 팀워크 +5·피로 −10 후 판정. 그대로 진행은 현재 값으로 판정. 피로 60 미만·팀워크 40 이상 성공, 실패 팀워크 −10·피로 +15 |
| 4개월 | 격려·기사 대응 후 쇼케이스 결과 확정. 팀워크 40 이상·신뢰 38 이상·기사 대응 완료·자금 1.5억 이상이면 성공. 예산 충분 시 1.5억 차감. 부족하면 비용 없이 실패로 진행. 성공 팀워크 +10·인지도 +8·피로 −5·팬 3천으로 설정. 실패 팀워크 −10·인지도 +2·피로 +15·신뢰 −3·팬 1천으로 설정 |
| 5개월 | 기본 홍보 4천만 원 또는 저예산 홍보 1천만 원이면 성공. 두 예산은 시연을 위한 고정 선택이며 별도 예산 배분 최적화 없음. 앞선 쇼케이스 성공이면 인지도 +10·팬 +1만·자금 +8천만 원, 실패였으면 인지도 +5·팬 +3천. 홍보 생략은 비용 없이 실패·인지도 −3. 자금 부족 시 유료 선택 거부, 생략 가능 |
| 6개월 | 기존 판정 재사용. 예능 훈련 이력이 있는 신입 출연 또는 다른 멤버 추천은 성공, 준비 없는 신입 출연은 실패, 거절은 수치 변화 없이 다음 장면. 성공 인지도 +8·팬 +1만·자금 +6천만 원, 실패 인지도 −5·피로 +10 |

격려 신뢰 +3은 월별 사건당 한 번만 반영한다. 재전송·반복 발언·이미 완료한 행동으로 효과를 다시 지급하지 않는다. 비용·보상·성패는 모델 대사로 확정하지 않는다. 원문의 더 복잡한 갈등·일정·세부 예산·개별 능력치 시뮬레이션은 이번 최소 구현에 포함하지 않았다.

## 연결 계약과 호환

`POST /api/games`에 `scenario`를 추가했다.

```json
{"character_id":"a", "scenario":"part2"}
```

- `part2`는 항상 이도 면담부터 시작한다. `character_id`는 기존 형식 호환을 위한 유효 후보 슬롯이며 최종 선발 결과가 아니다. 실제 선택은 선발 장면에서 확정한다.
- 생략 또는 `demo`이면 이전의 1 → 6 → 13 → 24개월 축약 경로가 유지된다. 기존 저장의 사건 ID·버전은 바꾸지 않는다.
- Part 2 사건 ID는 `p2_` 접두사를 쓴다. 기존 `Game`·턴·대화방·도입 응답 형태는 유지한다. 상태 필드는 새로 추가하지 않았다.
- 면담 종료 또는 선발 턴의 `turn.conversation`은 **발언한 이전 후보**, `game.character`와 현재 `game.conversation`은 **전환 후 후보/신입**이다. 과거 화자는 반드시 턴의 참여자 스냅샷에서 표시한다.
- 웹은 새 백엔드 적용 후 함께 배포한다. 이전 백엔드는 `scenario`를 허용하지 않아 422가 된다.
- 도입·선택·완료 후 종료 처리는 기존 계약을 재사용한다. `part2_complete`는 `game.ending`으로 전달하지만 최종 계약 엔딩과 구분해 표시한다.

## 개발 검증

실제 HTTP 경로로 세 후보 각각의 선발과 자유 입력만 사용한 전체 성공 경로, 실패·거절 경로, 후보별 대화 분리, 질문·부정·회상·복수 선발의 실행 방지, 비용 부족, 반복 보상, 저장·복원, 후보 전환 중 모델 오류와 동일 요청 재시도를 확인한다. 실제 유료 모델 품질 평가는 이 작업에서 수행하지 않는다.
