# 7~12개월 서버 연결 시 보존 기준

작성·사용자 확인: 2026-11-11. 사용자가 지정한 월별 흐름과 구체안을 현재 프런트 데모에 대조한 기준이다. 수상 소감의 공백 처리와 12개월 보상 적용 시점은 현재 데모 동작을 따르기로 확인했다.

이 문서는 **서버 연결 후에도 유지해야 하는 플레이 경험과 판정의 요구사항**이다. 현재 서버가 이 내용을 모두 구현했다는 뜻은 아니다. 이번 변경은 문서 작성이며 서버 연결·게임 코드 수정은 포함하지 않는다.

## 적용 범위와 우선순위

- 7~12개월 서버 연결, 이미 연결된 화면의 데모 흐름 복원, 관련 API·상태·저장 변경에 적용한다. 1~6개월과 13~24개월의 규칙을 임의로 변경하지 않는다.
- 기준 구현은 `7a655b33ee8b93d6e9cfa9e52c4558cf6268b49c`의 [PartThree.tsx](../../frontend/src/PartThree.tsx), [part3State.ts](../../frontend/src/part3State.ts), [part3.css](../../frontend/src/part3.css)와 해당 화면이 사용하는 공통 컴포넌트·스타일·사용자 제공 이미지다. 검토 진입점은 `/?part3Demo=1`이다. 이후 코드가 바뀌어도 이 기준을 자동으로 바꾸지 않는다.
- 과거 [Part 3 데모 기록](part3-prototype.md)은 구현 이력이다. 초안 저장, 무대 배경, 13개월 연결 등에 과거 설명이 있으므로 최신 코드와 이 문서를 함께 확인한다. API 계약은 [프런트 연결 명세](frontend-integration.md), 디자인은 [화면 방향](../design/ui-direction.md)을 함께 따른다.
- 기존 서버 동작을 이유로 아래 단계·선택지·면담·판정·연출을 생략하거나 기존 서버 화면으로 대체하지 않는다. 필요한 서버 기능과 응답을 구현하고 기존 화면에 연결한다.
- 이 문서와 데모가 다르거나 서버 연결 중 판정·수치·ID 매핑·전환·저장 이관 등에 해석이 필요한 부분이 있으면 **임의로 결정하지 않는다**. 현재 동작, 차이, 가능한 처리 방식과 영향을 사용자에게 제시하고 **확인받은 뒤 해당 부분을 변경한다**. 확인과 무관한 작업은 계속할 수 있다. 확인된 결정은 관련 명세에 반영한다.
- 화면 구성·진행 순서·선택지·필수 상호작용·전환 조건·수치 규칙을 바꿔야 하는 경우도 같은 확인 절차를 따른다. 화면을 유지하기 위해 서버 판정을 프런트에서 임의로 확정하거나 검증을 우회하지 않는다.

## 공통 화면·진행 규칙

- 7~11개월은 대표실, 12개월은 무대를 사용한다. 현재 배경 매핑은 `/images/scenes/office.png`, `/images/scenes/stage.png`다. 트로피 진열 장면은 나레이션이며 새 트로피 이미지·애니메이션을 요구하지 않는다.
- 나레이션은 공통 `NarrationScene`, 인물 대화는 기존 인물·흰 대사 영역을 유지한다. 배경·사진·인물 크기·배치·색상·버튼·입력창·PC/모바일 구성은 서버 연결 편의를 위해 변경하지 않는다. `PhotoSlot`, `ChatComposer`, `Modal`, 필요한 운영 화면의 `ResourceStatus`와 공통 디자인 규칙을 유지한다.
- 사용자가 다음 버튼으로 안내를 읽고 면담·선택 화면으로 넘어간다. 설명을 읽기 전에 선택을 자동 실행하거나 월을 자동 진행하지 않는다.
- 7개월은 신입, 10개월은 신입·리안·도하·세인 각각 사용자 발화 기준 최소 1회·최대 8회 면담한다. 첫 인사·대상 전환·질문 예시 선택은 횟수에 포함하지 않는다. 질문 예시는 초안만 채우고 사용자가 전송한다.
- 면담 중 모든 스텟은 유지한다. AI 답변이나 자유문 지시로 대응·센터 선택을 대신 확정하거나 월을 종료하지 않는다. 필수 면담 후 사용자가 면담을 마무리하고, 백하연 안내를 읽은 다음 선택한다.
- 선택 중에는 확정 전 초안이며 효과가 없다. 확인 창에서 다시 선택하거나 확정할 수 있어야 한다. 확정 후 결과를 표시하고 사용자가 다음 단계로 이동한다.
- 피로·팀워크·신뢰·인지도는 0~100, 팬·자금은 0 이상이다. 변화량은 범위 제한 후 실제 적용량으로 표시한다. 관리 효과처럼 순서가 정해진 계산은 각 단계의 제한도 지킨다.
- 고정 상황 안내·첫 발화·결과 연출과 선택지는 기준 데모를 유지한다. 데모 면담 답변은 임시 순환 대사다. 실제 AI 답변 연결은 면담 순서·대상·횟수·스텟 불변 규칙 안에서 수행한다.

## 7개월 · 악성 게시물 대응

배경: 대표실.

1. 악성 게시물과 확인되지 않은 소문이 확산된 상황을 나레이션으로 제시한다.
2. 신입이 “대표님, 상담할 게 있어서 왔어요”로 시작하는 현재 데모의 첫 발화를 한다.
3. 신입 면담을 진행한다. 최소 1회·최대 8회이며 스텟은 변하지 않는다.
4. 사용자가 면담을 마무리하면 백하연이 법적 대응과 SNS 관리를 각각 선택하도록 안내한다.
5. 안내 다음 화면에서 아래 두 항목을 각각 선택하고 확인 창에서 확정한다.

| 항목 | 선택지 |
|---|---|
| 법적 대응 | 증거 확보·법적 대응 / 법적 대응 없이 경과 관찰 |
| SNS 관리 | 공식 입장 발표·개인 SNS 잠시 중단 / 개인 SNS 활동 유지 |

| 조합 | 판정 | 효과 |
|---|---|---|
| 법적 대응 + 공식 입장·SNS 중단 | 성공 | 자금 −2천만, 신뢰 +5, 팀워크 +5 |
| 경과 관찰 + 공식 입장·SNS 중단 | 팀워크 50 이상 성공 | 성공: 신뢰 +3·팀워크 +3 / 실패: 신뢰 −5·팀워크 −5·피로 +10 |
| 법적 대응 + SNS 유지 | 실패 | 자금 −2천만, 신뢰 −5, 팀워크 −5, 피로 +10 |
| 경과 관찰 + SNS 유지 | 실패 | 신뢰 −5, 팀워크 −5, 피로 +10 |

법적 대응 비용은 성패와 별개로 한 번 차감한다. 자금 2천만 원 미만이면 법적 대응 선택을 막고 부족 상태를 표시한다.

6. 결과와 실제 수치 변화를 표시한다.
7. 결과 반영 후 **2~7개월이 모두 실패 또는 거절**이면 다음 진행 버튼은 ‘이야기 마무리’가 되고 잊혀진 그룹 엔딩으로 이동한다. 그 외에는 8개월로 이동한다. 1개월은 검사하지 않는다. 가져온 `neutral` 거절은 실패로 정규화하되, 누락 이력은 `null`로 보존하고 실패로 추정하지 않는다.

## 8개월 · 컨디션 관리

배경: 대표실. 7개월 성공이면 컨디션 점검, 실패이면 번아웃 경고다. 7개월 조기 엔딩에 진입했다면 이 달로 진행하지 않는다.

1. 전월 결과에 맞는 상황 나레이션을 표시한다.
2. 백하연이 관리 방법과 성공 기준을 안내한다.
3. 사용자가 선택 화면의 ‘컨디션 관리 선택’ 버튼을 누르면 관리 창을 연다.
4. 한 항목 선택 → 선택 확인 → 확정 순서로 진행한다. 유료 항목은 자금 부족 시 선택할 수 없고 휴가는 항상 가능하다.

| 관리 | 비용 | 피로 변화 |
|---|---:|---:|
| 휴가 제공 | 0원 | −25 |
| 건강검진 | 1천만 원 | −20 |
| 피부과 | 5백만 원 | −10 |
| 마사지 | 8백만 원 | −15 |

5. **관리 효과 적용 → 성공 판정 → 결과 효과 적용** 순서로 계산한다. 관리 직후 피로는 최소 0으로 제한한다. 컨디션 점검은 피로 30 이하, 번아웃 경고는 70 이하면 성공한다.
6. 성공은 피로 −15·팀워크 +5, 실패는 피로 +10·팀워크 −10을 적용한다. 최종 피로는 0~100으로 제한한다. 휴가에 별도 인지도 감소는 없다.
7. 결과 나레이션과 순변화를 표시한다. 다음 달 도입에서도 컨디션 관리 결과를 나레이션으로 이어간다.

## 9개월 · 신입 광고 제안

배경: 대표실.

1. 전월 컨디션 관리 결과를 나레이션으로 제시한다.
2. 백하연이 세 대사에 걸쳐 신입을 지목한 제안, 개인 노출의 기회와 팀 내 소외 위험, 전원 출연 협상 가능성을 설명한다. 짧은 단일 안내로 축약하지 않는다.
3. 설명을 끝까지 읽은 뒤 선택 화면으로 이동한다.
4. 단독 광고 수락 / 전원 광고로 협상 / 광고 거절 중 하나를 선택하고 확인·확정한다.

| 선택 | 확정 전 팀워크 | 판정·효과 |
|---|---|---|
| 단독 수락 또는 전원 협상 | 60 이상 | 성공: 자금 +1.2억·팀워크 +5·인지도 +10·신입 비주얼 성장 +1 |
| 전원 협상 | 60 미만 | 성공: 자금 +1억·팀워크 +10·인지도 +10 |
| 단독 수락 | 60 미만 | 실패: 자금 +1.5억·팀워크 −10·인지도 +5 |
| 광고 거절 | 무관 | 실패: 수치 변화 없음 |

5. 결과를 표시한다. 거절은 거절에 맞는 나레이션, 단독 수락 실패는 자금 확보와 소외감에 관한 나레이션으로 구분한다. 실패라도 표에 정해진 광고 수입은 지급한다.

비주얼 성장은 공통 `Stats`와 별도의 `visualGrowth`로 기록하며 이 구간의 다른 판정에는 사용하지 않는다. 서버 저장 필드·매핑이 불분명하면 사용자에게 확인하고, 성장 기록을 조용히 버리거나 다른 수치로 대체하지 않는다.

## 10개월 · 두 번째 컴백의 센터

배경: 대표실.

1. 9개월 성공이면 광고 효과·인지도 상승·팬 기대, 실패이면 조용한 컴백 준비를 나레이션으로 제시한다.
2. 백하연이 두 번째 컴백과 네 멤버 면담을 안내한다.
3. 신입·리안·도하·세인 각각 최소 1회·최대 8회 면담한다. 멤버 탭·각 면담 현황을 유지하고 면담 중 스텟은 변하지 않는다.
4. 네 멤버의 필수 면담을 마친 뒤 사용자가 면담을 마무리한다.
5. 백하연의 센터 선택 안내 → 선택 화면 → 센터 선택 → 확인·확정 → 결과 순서다.

| 조건 | 판정 | 효과 |
|---|---|---|
| 팀워크 60 미만이면서 신입 센터 | 실패 | 팀워크 −10·인지도 +3·팬 +3천·피로 +10 |
| 그 외 모든 경우 | 성공 | 팀워크 +8·인지도 +10·팬 +1만·피로 +5 |

신입 센터가 항상 실패하는 것은 아니다. 선택한 실제 센터 ID·이름을 저장하고 다음 달 나레이션에 반영한다. 화면 이름과 기존 내부 ID는 리안=`dahyun`, 도하=`haram`, 세인=`yuna`다. 신입은 실제 선발 프로필을 사용하며 서버 ID와의 대응은 명세에 명시한다.

## 11개월 · 수상 소감 준비

배경: 대표실.

1. 컴백 성공이면 실제 센터 이름과 무대 성과를 나레이션으로 표시한다. 실패이면 신입 센터에 대한 평가와 멤버 불만을 표시한다.
2. 백하연이 다음 달 연말 시상식과 신인상 가능성을 안내한다.
3. 이어 백하연이 신입이 대표로 말할 수상 소감 대본 작성을 안내한다.
4. 안내를 읽은 뒤 ‘수상 소감을 입력해주세요’ 입력 화면으로 이동한다.
5. 공백·줄바꿈을 포함한 입력 길이는 최대 500자다. 공백만 입력하면 확정할 수 없다. 확인 창에서 대본을 검토하고 확정한다. 확정 시 앞뒤 공백·줄바꿈은 제거하고 내부 공백·줄바꿈은 유지한다. 현재 구현은 JavaScript 문자열 길이 기준이다.
6. **확정 시 인지도 40 이상·팬 5만 이상을 모두 충족하면 수상 예정**으로 판정한다. 이 달에는 수상·미수상 보상을 적용하지 않는다.
7. 화면에는 ‘대본 작성 완료’와 시상식을 기다리는 나레이션을 표시한다. 수상 여부를 11개월 결과 화면에서 먼저 공개하지 않는다.

## 12개월 · 시상식과 반기 정리

배경: 무대. 트로피 진열 나레이션도 현재 데모의 배경·연출을 유지하며 대표실 배경으로 임의 전환하지 않는다.

11개월 결과에서 12개월 첫 나레이션으로 넘어갈 때 아래 보상을 **한 번만** 적용한다. 장면별 다음 버튼·새로고침·요청 재시도로 다시 지급하지 않는다. 반기 정리는 보상 반영 후 수치를 사용한다.

| 결과 | 효과 |
|---|---|
| 신인상 수상 | 팀워크 +10·인지도 +15·팬 +5만 |
| 미수상 | 팀워크 +3·인지도 +5·팬 +1만 |

수상 경로:

1. 쟁쟁한 경쟁 그룹 사이에서 신인상을 수상하는 나레이션.
2. 실제 선발 신입이 11개월에 확정·저장한 수상 소감을 그대로 발화한다. 다른 인물이 대신 말하거나 AI가 요약·재작성하지 않는다.
3. 울먹이며 인사를 마친 신입과 스페셜 무대 완료 나레이션.
4. ‘백하연이 트로피를 진열장에 하나 더 추가한다’는 나레이션.
5. 백하연의 반기 정리.

미수상 경로:

1. 다른 팀의 수상과 멤버들이 아쉬움을 달래는 나레이션.
2. 백하연의 반기 정리. 수상 소감 발화·트로피 추가 장면은 표시하지 않는다.

두 경로 모두 ‘반기 결산 마치기’로 완료 화면에 진입한다. 완료 화면의 기록 보기와 **13개월차 · Part 4 시작** 버튼을 유지하고 자동 진행하지 않는다. 다음 구간으로 실제 신입·목표·스텟·기록을 이어주는 기존 경험을 보존하며, 서버와 로컬 저장 사이의 이관 방식이 불명확하면 먼저 사용자 확인을 받는다.

## 서버 연결·저장 계약

- 프런트는 기존 화면과 선택 초안·팝업을 관리한다. 서버는 입력 검증, AI 답변 연결, 확정 수치·성패·분기·엔딩·영구 저장을 담당한다. 화면 표시를 위한 응답 변환을 허용하되 월별 흐름을 바꾸지 않는다.
- 현재 로컬 데모와 서버 저장은 별개다. 기존 데모 저장을 서버 저장으로 임의 간주·덮어쓰기·자동 업로드하지 않는다. 키 없는 명시적 데모 경로도 유지한다. 서버 오류를 성공한 데모 응답으로 대체하지 않는다.
- 서버 연결 후 확정 단계·읽던 위치·면담 대상과 횟수·대화 기록·선택·수상 소감·센터·결과·수치·보상 적용 여부를 복원해야 한다. 기존 저장의 누락 값이나 진행 단계를 임의 추정해 재판정하지 않는다.
- 현재 독립 데모는 확정 전 초안을 새로고침 후 복원하지 않고, 통합 브라우저 플레이는 선택·채팅·소감 초안을 저장한다. 두 경로를 혼동하지 않는다. 서버 연결 대상 경로와 초안 보관 방식을 명세에 명시하고 불명확하면 먼저 확인받는다.
- 처리 중·미해결 요청은 중복 전송을 막고 오류와 재시도를 제공한다. 같은 요청의 재시도·복원으로 대화 횟수·비용·보상·월 이동이 중복 적용되지 않아야 한다. 손상·충돌 저장은 원본을 보존하고 오류를 표시한다.
- 요청·응답 필드, ID·화자, 단계·전환, 표시 순서, 오류·재시도, 저장·복원 변경은 [프런트 연결 명세](frontend-integration.md)와 [types.ts](../../frontend/src/types.ts)에 함께 반영한다. 현재 지원·미구현, 변경일, 필요한 웹 수정과 적용 순서를 구분한다. 이 문서 자체를 현재 API 응답 계약으로 간주하지 않는다.

## 연결 완료 확인 기준

아래는 **향후 서버 연결 작업에서 수행할 검증**이며 이번 문서 작성에서 통과했다고 보고하는 항목이 아니다.

- 연결 전 데모와 연결 후 서버 화면의 같은 장면을 PC·모바일에서 비교한다. 월별 단계·화자·사진·배경·배치·버튼·선택 창·입력창·스크롤을 확인한다. 기존 서버 월별 화면이 열렸다는 사실만으로 흐름 보존을 완료 처리하지 않는다.
- 7개월 네 조합, 팀워크 49/50, 비용 부족, 2~7개월 전체 실패·일부 성공·누락 이력과 1개월 제외를 검증한다.
- 면담의 첫 발화, 1~8회 제한, 네 멤버 필수 면담, 스텟 불변, 안내 후 선택과 명시적 확정을 확인한다.
- 8개월 관리 직후 피로 30/31·70/71, 비용 부족, 피로 0 제한과 결과 효과 순서를 확인한다. 9개월 팀워크 59/60의 세 선택과 비주얼 기록, 10개월 팀워크 59/60의 네 센터를 확인한다.
- 11개월 인지도 39/40·팬 49,999/50,000, 공백만 있는 입력·500자 제한·앞뒤 공백 제거·내부 줄바꿈 보존, 12개월 실제 신입의 소감·수상/미수상 연출·트로피·보상 1회 적용을 확인한다.
- 6→7개월과 12→13개월 전환, 새로고침·이어하기·요청 재시도·저장 충돌 및 기존 1~6개월 회귀를 확인한다. 13개월 이후 동작은 연결부에 영향을 준 범위에서 확인한다.
- 관련 백엔드 pytest, 프런트 빌드·상태 테스트와 실제 키 없는 서버 연결 동작을 검증한다. 기존 [Part 3 상태 테스트](../../frontend/tests/part3-state.test.mjs)와 [플레이 흐름 E2E](../../frontend/e2e/playthrough.spec.ts)를 참고하되 로컬 데모 테스트 통과를 서버 연결 검증으로 보고하지 않는다. 유료 모델 호출·배포는 별도 요청 범위에서만 진행한다.
