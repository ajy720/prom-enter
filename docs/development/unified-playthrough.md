# 첫 화면부터 Part 3까지 통합 플레이

2026-11-10. 첫 화면 → 프롤로그 → 후보 면담·선발 → 1~2개월차 → 기존 3~6개월차 프런트 흐름 → Part 3(7~12개월차)를 기본 `/` 플레이 안에서 이어간다. 별도 데모 URL로 이동하거나 게임을 다시 생성하지 않는다.

## 상태의 경계와 호환

| 구간 | 현재 동작 | 저장·판정 |
|---|---|---|
| 프롤로그 | 기존 소개·호칭·후보 목록 | 기존 브라우저 도입 저장 |
| 후보 면담·선발, 1~2개월 | 기존 HTTP 요청과 서버 응답 유지 | 서버 DB·소유자 쿠키, 데모 provider 또는 설정된 실제 provider |
| 3~6개월 | 기존 별도 프런트 화면을 같은 플레이에 내장 | 같은 게임 ID 아래 브라우저 상태, 임시 대사·기존 예시 효과 |
| 7~12개월 | 확정된 Part 3 흐름을 내장 | 같은 게임 ID 아래 브라우저 상태, 확정된 프런트 프로토타입 규칙 |

`frontend/src/playthroughState.ts`의 `Playthrough`가 원본 서버 `Game` 스냅샷과 `SixMonthSave`, `Part3Save`를 묶는다. 키는 `prom-playthrough-v1:{game_id}`다. `prom-story-game`의 원래 ID와 `prom-active-save=story`를 계속 사용하며 서버 ID·후보·스텟·훈련·기존 기록·월별 결과를 유지한다. 서버의 `Game`, `TurnInput`, `Stats` HTTP 자료형은 변경하지 않았다.

- 2개월 종료의 결과·3개월 안내를 읽고 나면 해당 게임의 로컬 3개월 상태를 한 번 생성한다. 고정 이도가 아닌 실제 선발된 이도·여울·사야의 ID·이름·사진·면담 기록을 사용한다. 신입 예능 훈련 이력도 이어받는다.
- 6개월 결과·결산 뒤 **7개월차로**는 URL 이동 없이 같은 저장의 Part 3를 만든다. 2개월 결과는 원래 서버 사건에서, 3~6개월 결과는 내장한 프런트 흐름에서 가져온다. 거절은 Part 3 엔딩 검사에서 실패로 취급한다.
- 기존 서버 3~6개월을 이미 진행 중인 저장은 해당 서버 사건을 재시작하지 않고 기존 서버 화면으로 계속한다. `p2_complete`에 도달하면 같은 ID로 Part 3에 연결한다.
- 이미 만들어진 통합 로컬 저장은 타이틀의 **이야기 이어하기**에서 먼저 복원한다. 이 구간은 서버에 다시 쓰거나 서버 오류를 데모 성공으로 대체하지 않는다. 서버 요청이 미해결인 동안 구간을 전환하지 않는다.
- 별도 데모의 이전 전역 키는 삭제·덮어쓰기·자동 혼합하지 않는다. 그 경로들은 독립 검토용 호환 진입점으로 남지만 기본 플레이에서는 링크나 새 게임 없이 이어진다.
- 확정한 선택과 결과뿐 아니라 Part 3의 SNS·광고·센터 선택 초안·수상 소감 초안, 로컬 면담 입력도 같은 저장에 보존한다. 후보 면담에서 목록/대화방을 보고 있던 상태는 `prom-interview-view:{id}:{event_id}`로 복원한다.

## 오류와 중복 처리

- 서버는 기존 요청 ID·버전·소유자 쿠키 계약을 유지한다. 연결 끊김(상태 0)과 5xx는 원본 `TurnInput`을 보존하고 동일 ID로 재시도한다. 409는 최신 상태를 조회하며 임의로 재전송하지 않는다. 이미 커밋한 응답이 유실된 경우 서버 캐시로 중복 기록을 막는다.
- 로컬 저장은 `revision`을 비교하고 쓰기가 성공한 뒤 화면에 반영한다. 저장소 부족은 해당 동작을 반영하지 않고 같은 동작을 다시 시도하게 한다. 다른 화면에서 먼저 진행하면 덮어쓰지 않고 이어하기로 재조회하도록 안내한다.
- 손상되거나 다른 게임 ID의 저장은 오류로 표시하고 원본을 보존한다. 새 예시를 자동 생성하거나 기존 플레이로 조용히 되돌리지 않는다.
- 6→7개월차 전환은 완료된 6개월 상태에서만 가능하다. Part 3는 수상 보상을 12개월 진입 때 한 번 적용하며 소감 원문·스페셜 무대·트로피 추가·반기 정리 순서를 유지한다.

## 기획·구현의 현재 한계

3~6개월차는 기존 프런트 데모 규칙을 통합했다. 4·5개월차 성공 기준은 여전히 미확정이며, 접을 수 있는 **현재 구간** 안내에서 기존 임시 결과를 고른다. 새 판정식을 임의로 확정하지 않았다. 이 구간의 결과와 수치가 서버 DB에 동기화되는 것은 아니다. 3~12개월차의 실제 AI·서버 판정·기기 간 이어하기는 후속 범위다.

신인상 성공은 11개월 확정 시 인지도 40·팬 5만 이상이어야 한다. 기존 4·5개월차의 축약된 팬 보상으로는 기본 전체 경로에서 이 수치에 도달하지 못할 수 있으므로, 수상 성공 검증은 조건을 명시한 별도 테스트 상태를 사용한다. 이를 자연 플레이나 실제 AI 검증으로 보고하지 않는다. 무대 원본 배경이 없어 12개월은 임시 단색 배경을 유지한다. 사용자 제공 기존 인물·장소 이미지를 재사용하며 새 이미지나 공유 폴더는 사용하지 않았다.

## 검증 실행

```sh
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

`test:e2e`는 기존 서버와 충돌하지 않도록 API 18000·프런트 5179 포트를 사용한다. API는 항상 `AI_PROVIDER=demo`, 테스트 DB는 `backend/data/playthrough-e2e.sqlite3`이다. `backend/.venv`와 의존성이 필요하며 Python 경로를 바꾸려면 `PROM_TEST_PYTHON`을 지정한다. Windows는 기본 설치된 Edge의 격리된 테스트 프로필, 그 외는 Playwright Chromium을 사용한다. `PROM_TEST_BROWSER_CHANNEL`로 브라우저를 바꿀 수 있다. Chromium이 필요하면 `frontend`에서 `PLAYWRIGHT_BROWSERS_PATH=node_modules/.cache/ms-playwright`를 지정하고 `npx playwright install chromium`을 실행한다. 일반 개발 서버는 기존 API 8000을 유지하며 테스트 프록시만 `PROM_API_TARGET`으로 바꾼다. 설정 예시는 `frontend/.env.example`이다.

테스트 스크린샷·실패 trace는 `frontend/test-results/`에 남기며 커밋하지 않는다. PC 1440×1000과 Pixel 7 크기·터치 환경을 에뮬레이션한다. 실제 휴대전화나 실제 유료 모델의 동작을 뜻하지 않는다.

커밋·push·PR·merge·배포는 이 작업 범위에 포함하지 않는다.
