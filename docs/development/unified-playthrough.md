# 첫 화면부터 Part 3까지 통합 플레이

2026-11-10. 기본 `/`에서 첫 화면 → 프롤로그 → 후보 면담·선발 → 서버 1~6개월차 → 로컬 Part 3(7~12개월차)로 이어진다. 별도 데모 URL이나 게임 재생성 없이 같은 게임 ID를 사용한다. [확정 월별 규칙](monthly-server-rules.md), [HTTP 계약](frontend-integration.md).

## 상태의 경계

| 구간 | 현재 동작 | 저장·판정 |
|---|---|---|
| 프롤로그 | 기존 소개·호칭·후보 목록 | 기존 브라우저 도입 저장 |
| 후보 면담·선발, 1~6개월 | HTTP 요청 → 서버 확정 상태 표시 | 서버 DB·소유자 쿠키, demo 또는 설정된 실제 provider |
| 7~12개월 | 기존 Part 3 프런트 프로토타입 | 같은 게임 ID 아래 브라우저 저장 |

- 1개월차 흐름은 유지한다. 2·3개월차 멤버별 1~8회 면담, 4개월 대응, 5개월 예산, 6개월 채팅 결정은 서버에서 처리한다. 기본 화면은 `ServerPartTwo`이며 3개월 진입 시 로컬 `SixMonthDemo`로 바꾸지 않는다.
- 월 이동 응답이 도착하면 결과 나레이션과 스텟 변화부터 읽고 다음 달 도입으로 진행한다. 3개월 공개 중단 후 세인·신입 답변도 면담 전에 순서대로 읽는다. 읽는 위치만 브라우저에 보관하고 게임 수치를 직접 누적하지 않는다.
- 서버 6개월 결과와 결산을 읽고 **7개월차로**를 누르면 `Playthrough`를 만든다. `source`는 서버 `p2_complete`의 `Game`, `six=null`, `stage=part3`이며 Part 3에 선발 멤버·훈련·스텟·기록·2~6개월 결과를 넘긴다.
- 키는 `prom-playthrough-v2:{game_id}`다. 이전 v1 테스트 데모 저장의 이전은 하지 않는다. 기존 테스트 진행은 보존하지 않아도 된다는 사용자 요청에 따라 새 플레이 기준으로 검증한다. 이전 독립 DEV 데모는 기본 플레이와 분리해 남긴다.
- 7개월 이후 로컬 저장이 있으면 이어하기에서 우선 복원하고, 그 전에는 서버를 재조회한다. 후보 면담 목록/대화방과 월별 읽는 위치·예산 입력 초안은 별도 브라우저 키로 복원한다.

## 오류와 중복 처리

- 서버는 기존 요청 ID·버전·소유자 쿠키 계약을 유지한다. 연결 끊김(상태 0)과 5xx는 원본 `TurnInput`을 보존하고 동일 ID로 재시도한다. 409는 최신 상태를 조회하며 임의로 재전송하지 않는다. 이미 커밋한 응답이 유실된 경우 서버 캐시로 중복 기록을 막는다.
- 로컬 저장은 `revision`을 비교하고 쓰기가 성공한 뒤 화면에 반영한다. 저장소 부족은 해당 동작을 반영하지 않고 같은 동작을 다시 시도하게 한다. 다른 화면에서 먼저 진행하면 덮어쓰지 않고 이어하기로 재조회하도록 안내한다.
- 손상되거나 다른 게임 ID의 저장은 오류로 표시하고 원본을 보존한다. 새 예시를 자동 생성하거나 기존 플레이로 조용히 되돌리지 않는다.
- 6→7개월차 전환은 완료된 6개월 상태에서만 가능하다. Part 3는 수상 보상을 12개월 진입 때 한 번 적용하며 소감 원문·스페셜 무대·트로피 추가·반기 정리 순서를 유지한다.

## 기획·구현의 현재 한계

대화 의미에 따른 팀워크·피로도 변화와 실제 개별 능력치 증가는 팀원 구현 후 연결한다. 현재 월별 성공·실패는 서버에 저장된 스텟을 사용한다. 6개월 예능 준비는 기존 `training_history`의 예능 훈련 이력으로 확인하며, 실제 성장 이력이 구현되면 이 입력 계약을 맞춰야 한다. 7~12개월차는 여전히 로컬 프로토타입이며 서버에 동기화되지 않는다. 기기 간 이어하기는 지원하지 않는다.

신인상 성공은 11개월 확정 시 인지도 40·팬 5만 이상이어야 한다. 현재 4·5개월차의 팬 보상으로는 기본 전체 경로에서 이 수치에 도달하지 못할 수 있으므로, 수상 성공 검증은 조건을 명시한 별도 테스트 상태를 사용한다. 이를 자연 플레이나 실제 AI 검증으로 보고하지 않는다. 무대 원본 배경이 없어 12개월은 임시 단색 배경을 유지한다. 사용자 제공 기존 인물·장소 이미지를 재사용하며 새 이미지나 공유 폴더는 사용하지 않았다.

## 검증 실행

```sh
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

`test:e2e`는 기존 서버와 충돌하지 않도록 API 18000·프런트 5179 포트를 사용한다. API는 항상 `AI_PROVIDER=demo`, 테스트 DB는 `backend/data/playthrough-e2e.sqlite3`이다. `backend/.venv`와 의존성이 필요하며 Python 경로를 바꾸려면 `PROM_TEST_PYTHON`을 지정한다. Windows는 기본 설치된 Edge의 격리된 테스트 프로필, 그 외는 Playwright Chromium을 사용한다. `PROM_TEST_BROWSER_CHANNEL`로 브라우저를 바꿀 수 있다. Chromium이 필요하면 `frontend`에서 `PLAYWRIGHT_BROWSERS_PATH=node_modules/.cache/ms-playwright`를 지정하고 `npx playwright install chromium`을 실행한다. 일반 개발 서버는 기존 API 8000을 유지하며 테스트 프록시만 `PROM_API_TARGET`으로 바꾼다. 설정 예시는 `frontend/.env.example`이다.

테스트 스크린샷·실패 trace는 `frontend/test-results/`에 남기며 커밋하지 않는다. PC 1440×1000과 Pixel 7 크기·터치 환경을 에뮬레이션한다. 실제 휴대전화나 실제 유료 모델의 동작을 뜻하지 않는다.

## 검증 범위

프런트 상태 테스트·빌드, 백엔드 월별 경계·수치·면담 제한·저장·중복 방지 테스트, PC·모바일 브라우저의 실제 demo API 성공·실패 흐름을 검증한다. 브라우저 전체 경로는 후보·1~6개월차에 서버를 사용하고 7~12개월차에는 로컬 저장을 사용한다. 유료 AI·실기기·7~12개월 서버 동기화 검증을 뜻하지 않는다. 최신 실행 결과는 작업 완료 보고를 따른다.
