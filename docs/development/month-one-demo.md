# 1개월차 — 어색한 첫 합숙 프론트 데모

작성일: 2026-11-03. 기존 `codex/intro-ui`에서 영입 화면 다음에 연결했다.

후속 조정: [운영 시스템 참고](game-systems-reference.md)에 맞춰 팀 능력치를 네 항목으로 표시한다. 도입 장면의 이전/다음은 유지하고, 멤버 면담은 멤버별 말풍선 기록 창으로 다시 읽는다. 합숙 전 비서 안내의 면담 기록·확정 사진 재열람 버튼과 첫 달의 영입 결과·면담 기록 버튼은 제거했다. 자금은 첫 자금 안내에서 소개하고, 영입 후 비서 안내와 첫 달 왼쪽 상태 패널에 계속 표시한다. 아래 확인 기록과 이전 미리보기는 추가 당시 화면 기준이다.

## 원안과 구현 범위

근거는 [월별 사건 1개월차](../../storyline/02-monthly-events.md)와 [Figma 원문 S014](../../storyline/sources/figma-text.md#s014)다. 사용자 요청은 1개월차 프론트이며, 기존 화면과 연결하고 화이트·연핑크 디자인을 유지한다.

- 세 명 면담 → 한 명 영입 → 사진이 있는 영입 확정 창 → 비서의 프로뮤 결성·계약과 목표·월 단위 활동 안내 → 첫 합숙 시작 → 첫 합동 연습 → 신입의 걱정 → 첫 달 과제 순서다.
- 영입한 여울/이도/사야의 이름·사진 자리·상황 대사를 사용한다. 기존 멤버는 리안·도하·세인이다.
- 원안 과제는 훈련 분야 하나 지정, 기존 멤버 면담, 합숙 규칙 결정이다. 초기 팀워크 40·피로도 20은 참고 수치로만 표시한다.
- 첫 달 계획 확인·확정·저장·기록 열람까지 플레이할 수 있다. 2개월차로 넘어가지 않는다.

## 이번 데모에서 정한 기본값

원안에 없는 세부 선택지와 완료 기준은 프론트 시연용이다. 팀의 최종 게임 규칙으로 간주하지 않는다.

- 훈련은 보컬/댄스/비주얼/예능 중 하나다.
- 기존 멤버 세 명 각각과 준비된 주제로 1회 이상 대화해야 한다. 신입과의 추가 대화도 가능하다. 미지원 입력 안내나 비서의 훈련 우선 안내는 면담 완료로 세지 않는다.
- 합숙 규칙은 짝 연습/매일 짧은 대화/연습 종료와 휴식 중 우선 규칙 하나를 고른다.
- 훈련·규칙은 확정 전까지 변경 가능하며, 확인창에서 확정한 뒤에는 기록만 열람한다.
- 자유 입력은 준비된 주제(연습 소감·필요한 도움·격려)의 키워드로 응답한다. 추천 질문도 제공한다. 실제 AI가 아니다.
- 훈련을 고르기 전 여행·휴가·광고·예능 출연 입력에는 백하연이 실력 차이 해소를 우선하도록 안내한다. 일반적인 의미 분석을 구현한 것은 아니다.
- 사용자가 Figma Part 1 마지막을 참고해 안내하도록 요청하여, 그 안내에서는 2년 계약·쇼케이스까지 3개월을 사용한다. 다른 자료에 남은 기간 충돌이나 월별 게임 판정을 함께 변경한 것은 아니다.

## 파일과 저장

| 파일 | 역할 |
|---|---|
| `frontend/src/MonthOne.tsx` | 그룹 결성·첫 합숙·과제 선택·대화·확인·완료 화면 |
| `frontend/src/monthOneContent.ts` | 시연용 선택지와 캐릭터별 준비된 대사 |
| `frontend/src/monthOneState.ts` | UI 진행·과제 완료 조건·기록·저장 읽기 |
| `frontend/src/Prologue.tsx` | 기존 영입 결과에서 연결, 전체 진행 저장 |

기존 `prom-intro-v1` 저장에 `monthOne`을 추가한다. 이전 저장은 면담·영입을 유지하며 첫 달 상태는 버튼을 누를 때 만든다. 영입 전에는 첫 달에 진입하지 않는다. 영입 결과로 돌아갔다가 다시 들어오거나 새로고침 후 '이야기 이어하기'를 눌러도 첫 달 진행을 유지한다. 새 게임은 기존 방식대로 전체 프롤로그 진행을 초기화한다. 기존 서버 축약 데모 저장은 건드리지 않는다.

### 영입 확정 및 Part 1 마무리 추가

- [Figma Part 1 마지막 문구](https://www.figma.com/design/zvPBVmlcjPJzgtgfB6QXFg/prom--enter?node-id=7-4)를 브라우저 검색으로 확인했고 [원문 S042](../../storyline/sources/figma-text.md#s042)와 일치했다. Figma MCP는 편집 권한이 없어 읽지 못했으며 시각 디자인을 추출·복제한 것은 아니다.
- `RecruitmentResult.tsx`가 선택한 신입의 큰 사진과 기존 세 명의 작은 사진을 표시한다. 현재는 이름과 실루엣 자리 표시이며 임의의 인물 사진은 생성하지 않았다. 실제 사진은 `introContent.ts`의 `portrait`/`profile`, 비서는 `introAssets.secretary`에 넣는다.
- 영입 전 확인과 영입 후 확정 창은 별개다. 확정 창을 닫아도 영입은 유지되며 다시 열 수 있다.
- `interviews.recruitmentStep`은 사진 확정(0) → 비서 안내(1~3) → 안내 완료(4)로 저장한다. 완료 전에는 첫 합숙 진입 동작이 열리지 않는다. 기존에 첫 달에 진입한 저장은 완료 상태로 호환하며 첫 달 기록을 초기화하지 않는다.
- 비서가 네 명의 그룹·프로뮤의 2년 계약·3개월 후 쇼케이스·한 달 단위 활동과 신입 훈련/적응 목표를 설명한다. 계약은 대표 개인이 아닌 프로뮤에 적용되며, 사용자는 이 기간 동안 프로뮤를 성공으로 이끌어야 한다(사용자 정정). 왼쪽 팀 상태는 첫 달 초기 안내값 40/20이다. 실제 게임 결과 계산은 계속 서버 연결 후의 작업이다.
- 새 플레이에서 영입 후 창 열림·닫기/다시 열기·중간 안내 저장 복원·모바일 안내 후 합숙 진입을 확인했다. 상태 테스트 6개와 빌드가 통과했다.

## 백엔드·AI 연결 시 남은 작업

현재 확정하는 것은 **브라우저 데모의 계획**이다. 게임 수치·훈련 효과·신입 신뢰도·멤버 불만·성공/실패를 계산하거나 실제 운영 결과를 확정하지 않는다. 원안 성공/실패 화면의 수치를 임의 조건으로 연결하지 않았다.

실제 연결 시에는 서버가 소유자·상태 버전·중복 요청을 확인해 선택과 대화를 저장하고, 훈련·규칙·신뢰도·불만에 따른 결과를 계산해야 한다. 이 UI의 `MonthOneState`는 서버/AI 팀과 합의한 API 계약이 아니다. 기존 HTTP·AI 호출 형식이나 팀원의 최신 AI 기능을 이번에 변경·병합하지 않았다.

- 중간 새로고침·영입 결과 왕복·확정 후 새로고침에서 복원 확인. 모바일 390px에서 가로 넘침 없음과 계획 확정 동작 확인.
