# 연습생 면담 데모

작성일: 2026-11-02. 사용자가 이번 대화에서 확정한 흐름과 구현 기본값을 구분한다.

2026-11-03: 최신 노션에 맞춰 공개 프로필과 데모 대사를 여울·이도·사야 기준으로 갱신했다. 내부 ID와 저장 키, 면담 규칙은 유지했다. 아래 2026-11-02 확인 기록의 이름은 당시 화면 기준이다. 상세 대응은 [캐릭터 참고](character-reference.md)에 있다.

후속 연결: 영입 후 멤버 사진이 있는 확정 창과 비서의 세 단계 목표 안내를 거쳐 [1개월차 프론트 데모](month-one-demo.md)로 진입한다. 실제 월별 게임의 서버 판정은 아직 연결하지 않았다.

## 확정한 흐름

- 여울·이도·사야 세 명의 면담을 모두 완료해야 최종 영입을 할 수 있다.
- 순서는 플레이어가 정한다. 후보마다 `면담 전 → 면담 중 → 면담 완료`로 관리한다.
- 목록으로 돌아가는 것은 완료가 아니다. 진행 중인 후보는 기록을 유지한 채 이어서 면담한다.
- 중앙 반신 사진, 왼쪽 후보 정보와 진행 상태, 하단 대사와 입력창을 사용한다. 추천 질문과 전체 대화 기록을 제공한다.
- 플레이어가 직접 마무리할 수 있고, 계속 대화하면 백하연이 등장해 마무리한다.
- 세 명 완료 후 별도 화면에서 한 명을 선택하고 영입 확인을 거친다.

## 이번 구현의 기본값

- 답변을 한 번 받은 뒤 수동 마무리가 가능하다. 완료 후에는 기록만 열람한다.
- 후보당 사용자 질문 8회에 답변하면 비서가 자동으로 마무리한다. 응답 실패나 첫 인사는 횟수에 포함하지 않는다. 무응답 대기 시간을 기준으로 종료하지 않는다.
- 8회는 개발 기본값이며 원안의 확정 수치가 아니다. `frontend/src/interviewState.ts`의 `AUTO_FINISH_TURNS`에서 변경한다.
- 영입 확정 후에는 이번 플레이에서 바꿀 수 없다. 새 게임을 시작하면 별도 진행으로 초기화한다.
- 상태와 기록은 기존 프롤로그 저장 키 `prom-intro-v1`의 `interviews`에 저장한다. 기존 저장에는 빈 면담 상태를 추가한다. 브라우저·기기 간 공유하지 않는다.

## 데모 대화와 AI 연결 지점

노션 설정을 바탕으로 대사를 새로 작성했다. 여울은 열정과 성장, 이도은 보컬과 무대 긴장, 사야는 실력과 팀 적응을 중심으로 말한다. 추천 질문 세 개와 꿈·강점·걱정·팀·격려 주제를 지원한다. 그 외 입력에는 캐릭터별 일반 안내를 반환한다. 이전 발화를 이해하거나 새로운 답변을 생성하는 실제 AI가 아니다.

`frontend/src/interviewProvider.ts`의 `InterviewProvider`는 **프론트 내부 연결 형식**이다. 백엔드/AI 팀과 합의된 HTTP 계약이 아니다.

| 항목 | 현재 형식 |
|---|---|
| 입력 | `requestId`, `traineeId` (`seoyeon`, `hyerin`, `jiwoo`), `message`, `history` |
| 기록 항목 | `id`, `speaker` (`player`, `trainee`, `secretary`), `text` |
| 성공 | `Promise<{ text: string }>` |
| 실패 | Promise 거절 → 오류 표시, 동일 요청으로 재시도 또는 질문 수정 |
| 취소 | `AbortSignal` 전달; 화면을 나가면 요청 취소 |

현재 `demoInterviewProvider`가 브라우저에서 준비된 답변을 반환한다. 화면의 '데모 면담' 표시로 구분한다. 전송 중 입력·추천 질문·마무리·상대 변경을 막는다. 실패한 턴은 기록과 횟수에 반영하지 않고 재시도할 때 같은 요청 ID를 사용한다. 실제 AI 실패를 데모 성공으로 대체하지 않는다.

실제 연결 때는 이 함수를 백엔드 호출 어댑터로 교체하고, 후보 ID를 캐릭터 설정에 매핑한다. 후보 ID는 모델 ID가 아니다. 모델과 API 키는 서버에서 관리한다. 브라우저 기록을 서버의 신뢰할 수 있는 맥락으로 간주하지 않고 서버 저장을 읽어 AI에 전달해야 한다.

실제 플레이로 확장할 때는 후보별 기록·완료 판정·8회 종료·최종 영입 검증도 서버로 옮긴다. 소유자 확인, 상태 버전, 중복 요청 방지와 함께 HTTP 입력·응답·오류 형식을 팀원과 합의한다. 기존 `/api/games`와 AI `analyze()`/`generate()` 계약은 이번에 수정하지 않았다. 이 면담의 영입 결과와 월별 운영 게임은 아직 연결하지 않았다.

- 프론트 빌드 및 Node 내장 테스트 3개 통과: 세 명 완료 조건, 중복 요청·8회 자동 종료, 저장 복원과 후보별 격리.
