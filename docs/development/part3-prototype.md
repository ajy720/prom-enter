# Part 3 프런트 데모 · 7~12개월차

2026-11-10. 사용자 확정 흐름과 선택·보상 구체안을 구현했다. 서버 코드·API·AI provider는 변경하지 않는다. 임시 대사는 입력 의미를 분석하지 않으며, 이 문서의 판정은 브라우저 데모 전용이다.

후속 통합: 이제 기본 `/`의 첫 화면부터 같은 게임 ID로 7~12개월차까지 이어진다. 아래 별도 URL·전역 키는 독립 검토 경로의 기록이며, 기본 진입·저장·검증은 [통합 플레이](unified-playthrough.md)를 우선한다.

## 실행과 연결

- `frontend`에서 `npm run dev` 후 `http://127.0.0.1:5173/?part3Demo=1`로 바로 진입한다. 서버 없이 동작하며 빌드 결과에도 이 명시적인 데모 진입점이 포함된다.
- 개발 중 `/?sixMonthDemo=1`의 6개월차 결산에서 **7개월차로 · Part 3 시작**을 누르면 신입·스텟·기존 월별 결과를 복사한다. 기존 서버 플레이의 `p2_complete` 결산에서도 별도 프런트 데모로 이동할 수 있다.
- 이미 Part 3 저장이 있으면 이를 먼저 복원한다. 다른 6개월차 결과를 다시 가져오려면 데모 안내 안의 **6개월차 결과로 새로 시작** 또는 **기존 플레이의 6개월차 결과로 새로 시작**을 누르고 교체를 확정한다. 기존 서버와 Part 2 데모 저장은 수정하지 않는다.
- 직접 진입 예시: 이도, 팀워크 55·피로 45·신뢰 40·인지도 25·팬 25,000명·자금 10억. 이전 결과가 없는 월은 `null`로 남기며 실패로 만들지 않는다.
- 저장: `localStorage.prom-part3-demo-v1`. 기존 서버의 6개월차 원본 전달은 `sessionStorage.prom-part3-source-v1`. `Part3Save`·명령·화자는 `frontend/src/part3State.ts`에서 정의한다. 서버 `Game`·`TurnInput`·`Stats` 계약에 필드를 추가하지 않는다.
- 확정한 선택, 결과, 읽는 단계, 멤버별 대화, 수상 소감과 스텟을 저장한다. 확정 전 선택 버튼·작성 중 채팅 및 소감 초안은 새로고침 시 초기화된다. 손상된 저장은 오류로 표시하고 자동 덮어쓰지 않는다. 저장소 쓰기 실패도 화면에 알린다.

## 흐름과 판정

1. **7개월**: 대표실 나레이션 → 신입 첫 발화 → 신입 면담 → 백하연 안내 → 법적 대응·SNS 관리 각각 선택 → 확인·결과. 법적 대응은 2천만 원이며 자금 부족 시 선택 불가. 법적 대응+공식 입장·개인 SNS 중단은 성공(신뢰 +5·팀 +5). 경과 관찰+공식 입장·중단은 팀워크 50 이상 성공(신뢰 +3·팀 +3). 나머지는 실패(신뢰 −5·팀 −5·피로 +10). 법적 대응 비용은 성패와 별개다. 2~7개월 전부 실패일 때만 잊혀진 그룹 엔딩. `neutral` 거절은 가져올 때 실패로 정규화하며, 1개월은 검사하지 않는다.
2. **8개월**: 7개월 성공이면 컨디션 점검, 실패이면 번아웃 경고. 나레이션 → 백하연 안내 → 관리 버튼·관리 창. 휴가(무료·피로 −25), 건강검진(1천만·−20), 피부과(5백만·−10), 마사지(8백만·−15) 중 하나. 관리 후 피로 30 이하(점검) 또는 70 이하(경고)면 성공. 이후 성공은 피로 −15·팀 +5, 실패는 피로 +10·팀 −10. 관리 효과와 결과 효과를 차례로 적용한 순변화를 표시한다.
3. **9개월**: 컨디션 결과 나레이션 → 백하연의 광고 상황 설명 3개 대사 → 선택. 팀워크 60 이상이면 단독·전원 광고 모두 성공(자금 +1.2억·팀 +5·인지도 +10·비주얼 성장 +1). 60 미만이면 전원 협상 성공(+1억·팀 +10·인지도 +10), 단독 수락 실패(+1.5억·팀 −10·인지도 +5). 거절은 팀워크와 무관하게 실패·변화 없음. 비주얼은 공통 스텟을 확장하지 않고 로컬 `visualGrowth`로 기록한다.
4. **10개월**: 광고 성공은 인지도 상승과 팬 기대 나레이션, 실패는 조용한 컴백 준비 나레이션 → 백하연이 두 번째 컴백 센터를 네 멤버 면담으로 결정하라고 안내 → 신입·리안·도하·세인 면담 → 마무리 → 백하연의 센터 선택 안내 → 선택. 팀워크 60 미만이면서 신입 센터일 때만 실패(팀 −10·인지도 +3·팬 +3천·피로 +10). 그 외 성공(팀 +8·인지도 +10·팬 +1만·피로 +5).
5. **11개월**: 컴백 결과 나레이션(성공 시 실제 센터 이름) → 백하연 시상식·소감 작성 안내 → 1~500자 소감 입력·확정. 확정 시 인지도 40 이상이고 팬 5만 이상이면 수상 예정. 보상은 아직 적용하지 않는다.
6. **12개월**: 무대. 수상 시 수상 나레이션 → 신입이 소감 원문을 발화 → 스페셜 무대 나레이션 → 백하연이 트로피를 진열장에 하나 더 추가하는 나레이션 → 백하연 반기 정리. 미수상 시 아쉬움을 달래는 나레이션 → 반기 정리. 진입 시 한 번만 수상 보상(팀 +10·인지도 +15·팬 +5만) 또는 미수상 보상(팀 +3·인지도 +5·팬 +1만)을 적용한다. 12개월 결산에서 종료하며 13개월로 넘어가지 않는다.

면담은 사용자 발화 기준 멤버별 최소 1회·최대 8회다. 첫 인사·상대 전환·질문 예시 초안 선택은 횟수를 소비하지 않는다. 면담 중 스텟은 변하지 않는다. 중복 대화 ID와 확정 후 재결정은 중복 효과를 만들지 않는다. 피로·팀워크·신뢰·인지도는 0~100, 팬·자금은 0 이상으로 제한한다.

## 디자인과 검증

기존 `month-photo-stage`의 정보·인물·흰색 대화 영역, 멤버 탭, `ChatComposer`, `ResourceStatus`, `Modal`을 재사용한다. 새 이미지를 만들거나 원본을 편집하지 않았다. 대표실은 제공된 `office.png`, 인물은 기존 ID의 배경 제거본이다. 이미지 기준은 사용자 제공 파일이다. 무대 배경 원본은 로컬에 없어 12개월차는 임시 단색 배경이며 추후 제공 원본을 연결해야 한다.

- `npm run build` 및 `node --test tests/*.test.mjs`로 빌드·93개 상태 테스트 통과(Part 3 신규 10개 포함).
- 신규 테스트는 7개월 대응 조합·2~7개월 엔딩·면담 1~8회·중복 요청·스텟 불변·피로 30/70·팀워크 50/60·광고 선택·센터 선택·인지도 40/팬 5만·소감·트로피 순서·보상 중복 방지·복원·전체 진행을 확인한다.
- 최초 독립 구현 당시 UI 도구 연결 실패로 브라우저 검증을 하지 못했다. 후속 통합에서 Playwright와 격리된 Edge로 PC·모바일 에뮬레이션 전체 전환과 오류·수상·실패 경로를 검증했다. 최신 결과와 실제 서버/로컬 샘플의 구분은 [통합 플레이](unified-playthrough.md)를 따른다. 실제 기기 IME·유료 모델·3~12개월 서버 판정·배포는 수행하지 않았다.
